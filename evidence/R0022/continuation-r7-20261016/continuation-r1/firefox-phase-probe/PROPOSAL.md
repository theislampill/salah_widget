# Bounded Firefox capture-phase observation

Status: proposed only. No copied browser has been prepared or launched.

The unchanged R7 full-card PNG attempt produced 427 of 1,200 requested images in 60 seconds. Its inner native screenshot interval had median 116.837 ms, p95 141.535 ms, and maximum 299.629 ms. Every conservative adjacency exceeded the unchanged 100 ms bound. Original PNGs, raw native responses and the failed chronology are retained. Earlier native JPEGs and WebM recordings also contain pale frames. Neither a later healthy PNG nor an encoder hypothesis resolves those failures.

The currently exposed Firefox method returns one combined result after `currentWindowGlobal.drawSnapshot`, canvas construction/copy and synchronous `toDataURL`. No currently exposed RPC reports those internal intervals. Changing the outer transport cannot remove time already inside this call. We need to identify whether a faster, faithful observation route is supported before changing it.

The exact proposal is `proposal.patch`, bound by `MANIFEST.json`. It adds bounded phase timestamps and document/context identities to the existing screenshot response, plus four explicitly selected 200 ms delay controls. Normal capture adds no await or microtask yield. The original snapshot, retry, dimensions, canvas copy, PNG encoding and returned image bytes remain in their existing order. The original code and all failed evidence remain available. This proposal does not modify the native screencast producer.

Only two members of an isolated copy of the installed Firefox `omni.ja` change: Juggler `PageHandler.js` and `Protocol.js`. All other decoded archive members and every other copied distribution file must match the installed source. The installed browser, compiled executable/libraries, personal profiles, product source, H1 parameters, performance limits and release authority do not change. No SDK build or new dependency is involved. The copy is never used as an accepted production browser merely because this diagnostic executes.

The proposed executable sequence, after exact owner approval and independent review, is `prepare_copy.py`, then `run_probe.py`. The carrier requires a bound owner-decision record, the exact reviewed packet and unchanged source/copy inventories; it records the actual Python and imported Pillow identities. One serial run captures 16 original full-viewport PNGs from initial loading, then 16 after the recorded ready/current/refined check, followed by one actual delay control per phase. The second block does not claim independently current state for every image. All requests, original responses, pixels, errors, partial outcomes and actual browser closure are preserved. These 36 observations are a phase diagnostic, not a new temporal acceptance campaign. No cadence or CPU PASS follows from them.

The offline consumer checks exact request/session/PNG association against the complete protocol transcript; ordered phase boundaries, real retry attempts, monotonic clock observations, configured parent/product identity and each label's exact actual delay phase are mandatory. Initial about:blank documents are explicitly retained as pre-product observations. The recorded ready/current/refined state must match the ordinary Orlando site and generation; it is not per-image currentness proof. Clock spacing is reported as observed spacing, not a claimed resolution guarantee. Phase intervals include observation overhead. Exact transformed-handler operation tests and negative association/aggregate tests precede the run. Original pixels still require independent inspection.

The result determines the next bounded action: if snapshot dominates, retain the capture/surface limitation and identify the actual missing compositor observation capability; if synchronous PNG encoding or canvas reconstruction dominates, propose only the demonstrated observation-side correction, preserving identical full-scene pixels and independently requalifying its chronology. A source change cannot be justified by this proposal before the measurements exist. Phase evidence alone will not classify the pale recordings as product or capture defects, and will not recover absent frames. A later alternative observer can satisfy the RLGWO only through its own complete source-bound chronological pixels and negative controls under the unchanged contract.

Smallest owner decision: authorize this exact disposable two-member tooling observation extension and its one bounded diagnostic run. It supplies missing causal evidence without expanding R0022 product ownership or merge authority. No unidentified external tooling recipient is required.

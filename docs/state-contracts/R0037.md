## 1. ISM-BLD-010 — frozen V1 verification (implemented)

**Identity and scope.** `tools/verify_v1.py` proves that V1's bytes are unchanged and, with `--check-pages`, runs a
bounded preflight that the root Pages configuration does not drop V1. It is not a deployment or readback claim.

**Canonical owner.** `tools/verify_v1.py` is the only verifier. The reviewed-configuration record
`REVIEWED_JEKYLL_CONFIGS` lives in that file next to `MANIFEST_SHA256`. Each entry maps a configuration SHA-256 to
a repository-relative evidence file.

**Dimensions.** (a) payload: manifest anchor, file digests, extras, checkout attributes; (b) `--check-root`;
(c) `--check-pages`: Jekyll configuration state × front matter; (d) `--negative-control`.

**States of (c).** `nojekyll` (`.nojekyll` present); `none` (no `_config.yml`, `_config.yaml`, `_config.toml`);
`reviewed` (exactly one configuration, digest listed, evidence JSON lists the four V1 public files with the tree's SHA-256 and, where given, byte count); `unreviewed` (digest not listed);
`evidence-missing` (digest listed, evidence file absent); `ambiguous` (more than one configuration file).

| Event / state | Guard | Result |
|---|---|---|
| any mode | manifest anchor or a payload digest differs, extra file, attributes changed | FAIL; short-circuits every other check (unchanged) |
| default mode | payload intact | `PASS: frozen V1 payload and anchored manifest` (unchanged) |
| `--check-pages`, `nojekyll` | — | PASS `...; .nojekyll present (Jekyll processing off); inclusion preflight only; deployment not checked` |
| `--check-pages`, `none` | — | PASS `...; no Jekyll configuration file; inclusion preflight only; deployment not checked` |
| `--check-pages`, `reviewed` | digest ∈ `REVIEWED_JEKYLL_CONFIGS`, evidence `is_file()`, and it names each of `v1/index.html`, `v1/config.js`, `v1/VERSION.json`, `v1/MANIFEST.sha256` (object keyed by path, or list items with `path`) with the tree's SHA-256 | PASS `...; reviewed Jekyll configuration <name> <sha256>; inclusion preflight only; deployment not checked` |
| `--check-pages`, `unreviewed` | digest ∉ set | FAIL `Jekyll configuration <name> <sha256> has no recorded V1 inclusion review` |
| `--check-pages`, `evidence-missing` | evidence path absent | FAIL `Jekyll configuration <name> <sha256> review evidence missing: <path>` |
| `--check-pages`, `evidence-unparseable` | evidence is not JSON | FAIL `... review evidence is not JSON: <path>` |
| `--check-pages`, `evidence-incomplete` | a V1 public file is absent from the evidence, or its SHA-256/byte count differs from the tree | FAIL `... review evidence <path> does not list <v1 file> with the tree's SHA-256` (one line per file) |
| `--check-pages`, `ambiguous` | two or more configuration files | FAIL `More than one Jekyll configuration file (ambiguous build input): <names>` |
| `--check-pages`, any | a V1 manifest file starts with `---` | FAIL `Unexpected front matter: <name>` (in practice the payload FAIL comes first) |
| `--check-root` | after the root overhaul | expected FAIL; pre-overhaul check only; removed from the current recipe |
| `--negative-control` | — | disposable tampered copy rejected with exactly `Frozen payload changed or missing: v1/index.html` (unchanged) |

**Invariants.** V1 bytes and `MANIFEST_SHA256` unchanged. No reachable permanently-red state for a correct tree. No
PASS text claims deployment. The verifier writes nothing in the repository; `--negative-control` writes only into a
temporary directory. Exit codes stay 0/1.

**Failure and recovery.** An unreviewed configuration fails; recovery is recording a review, never deleting the
check. A reviewed digest whose evidence is later found wrong is removed from the set and FAIL returns. A
configuration change merged without re-review fails on the next run (no gate runs on `main` until R002A, issue 91).

**Configuration-file lookup.** Jekyll reads the first existing of `_config.yml`, `_config.yaml`, `_config.toml`
unless `--config` is given. This follows Jekyll's documented default; it was not re-measured against the hosted
`jekyll-build-pages:v1.0.13` builder (residual). Two files are treated as ambiguous rather than assuming that order.

### Admitting a Jekyll configuration

Whoever edits a Jekyll configuration file owns its re-review. In the same change:

1. Produce evidence of kind (i): a build-equivalent Jekyll build or a measured deployed Pages artifact of exactly
   that configuration, showing `v1/index.html`, `v1/config.js`, `v1/VERSION.json` and `v1/MANIFEST.sha256` present
   and byte-identical to the tree. Static reasoning about `exclude` is supporting reasoning only, never the review.
2. Retain it in the repository and add **one** entry `"<sha256>": "<evidence path>"` to `REVIEWED_JEKYLL_CONFIGS`.
   Earlier entries may stay (they no longer match and are inert) or be removed.
3. Run `python tools/verify_v1.py --check-pages` and `python tests/test_verify_v1_pages.py`.

The verifier checks that the digest is listed and that its evidence names the four V1 public files with the tree's
SHA-256 (hardening adopted from the R0037 review). Whether the evidence really measures a site built from that
configuration is judged by the reviewer of that change.

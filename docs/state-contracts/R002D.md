## 1. Implemented contract

### 1.1 ISM-PRAY-009 — live zone authority

- **Authorities.** (1) The configured hint, set by Bind. (2) The adopted location zone, set from admitted prayer metadata. Live `tz` is the adopted zone once one is adopted for the current generation; until then it is the effective hint.
- **Effective hint.** `_cacheTz`. It is frozen at binding and is also the R0004 cache-key zone. A rejected hint gives the absent-hint default `America/New_York`, so the cache key is the same as for an absent hint (I-2).
- **Admission predicate** (`admissibleZone` in `src/native/index.html`, `admitZone` in `src/native/config.js`). A zone is admitted when it is a non-empty string, not an offset (`/^[+-]/`), and accepted as `Intl.DateTimeFormat` `timeZone` by this engine. This is the rule `admitPrayerRecord` already used. The extraction is behaviour-identical: r0002-admission is unchanged. A table test proves both modules agree.
- **Writers** (no others assign `tz`):

| Writer | Site | Guard |
|---|---|---|
| W1 Bind | `bindConfig` | `admissibleZone(c.tz)`, else the default; clears `_tzAdopted`/`_tzAdoptedSource` |
| W1b legacy fallback (config.js absent) | the degraded hash parser | `admissibleZone(q.get("tz"))`, else the default; then W1 re-admits (defence in depth) |
| W2 cache adoption | `loadPrayerData` | `requestEligible` and an admitted envelope; source `cache` |
| W3 network adoption | `loadPrayerData` (bootstrap and the one corrected day) | `prayerResultEligible` and admitted metadata; source `network` |
| W4 current-day record | `adoptPrayerBundle` | admission and the exact civil day; a prefetch cannot change the present zone; source `record` |

`config.js` `normalize` applies the same predicate. Coarse detection, stored configs, hash configs and settings configs are therefore all admitted before binding.

- **Effects of a zone change.**
  - Z-1: formatter caches re-key (unchanged).
  - Z-2: the civil day is recomputed (unchanged).
  - Z-3: fragment anchors re-anchor in the new zone (unchanged).
  - Z-4: control anchors do not re-anchor (§1.2).
  - Z-5: the wall-mode scene identity and the refined-sky capture zone do not change (§1.3).
  - Z-6: weather operations keep their captured `requestZone` (unchanged).
- **Invariants.**
  - I-1: live `tz` is admissible.
  - I-2: a rejected hint never reaches `tz`, `prayerCivilDay`, `initSim` or a request URL, on either path.
  - I-3: no provider request is issued for an unresolved civil day. `fetchTimings` throws before creating any slot when `prayerNextDay(dateStr)==null`. `beginPrayerRequest` returns `null` with no owner and no cooldown.
  - I-4: an admitted hint keeps byte-identical `_cacheTz`, cache keys and request sequences (R0004).
  - I-5: a next-day record cannot change the present zone (unchanged).
- **Failure and recovery.** A rejected hint falls back to the default. Provider adoption then supplies the location zone within the existing corrected-day budget. An unresolved day from any other cause issues no request. `maintainPrayerDay` retries on a later frame once the day resolves (no busy request loop).
- **Diagnostics.** `qaState().zone = {configured, admitted, effective, adopted, source, live, anchor}` is a pure, best-effort read. For a fragment-sourced config, `configured` is the raw `#tz=` value. No visible text changed.

### 1.2 ISM-PRAY-001 — anchor kind

`_anchorKind` takes three values:

- `wall` (FOLLOW_WALL_CLOCK)
- `fragment` (URL `simTime`/`timeScale`; zone-relative)
- `control` (`SalahClock.set` with `live:false`; an absolute UTC instant)

`SalahClock.set({live:true})` sets `wall`, and any other accepted set sets `control`. `simNow` re-anchors on `_simTz!==tz`, and keeps invalid-scene stickiness, only for non-control anchors. `_clockPreview` is true exactly while the anchor is `control`. `SalahClock.set` still validates before it mutates anything.

### 1.3 ISM-SKY-001 — identity

`skySceneIdentity()` is `lat|lon|_cacheTz|wall`, or the existing explicit-anchor suffix. It changes only when the target, the anchor or a configuration Bind changes. This is the same string `native-first-paint.mjs` computes (`c.tz||'America/New_York'` of the normalized config).

`real-sky/native-host-hooks.js` reports `tz:_cacheTz`. Isolated hook fixtures that bind no configuration fall back to the live `tz`. `nativeIdentity` is unchanged, so the accepted "timezone-only update invalidates" contract test still holds. `moonGeometryIdentity` keeps the live `tz`. The initial head is still retired at `finishInitialSkyDocument` before any acquisition await.

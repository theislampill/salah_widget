## 1. Implemented contract

### 1.1 ISM-SKY-006 — target identity (PRA-F-10, D-F02 half)

- **Owner.** `real-sky/native-contract.mjs` owns `nativeIdentity`; `nativeJob` derives its weather terms from the same
  private record `nativeWeatherInputs(s)` = `{accepted, source, visibilityFactor, temperatureC}`.
- **Identity rule.** The identity array is unchanged except its weather element, which is now
  `null` (no weather) or `[source, visibilityFactor, temperatureC]`, where `visibilityFactor = clamp01(1 - vis/20000)`
  (the aerosol term) and `temperatureC` is the clamped observer temperature after the unit conversion. Values are exact.
  - Completeness: every job field that reads the snapshot (observer, options, native labels, acceptance flag) is a
    function of an identity element. Shown by ES34-02 and by a 40,000-snapshot differential: `nativeJob` on this branch
    equals `nativeJob` on `main` byte for byte except the identity label (scratch probe `jobeq.mjs`, randomised over
    weather presence, `src`, `temp` incl. non-finite, `vis` incl. saturated/negative, units, lp, motion, estimates,
    both physical flags).
  - Minimality: `rh`, `cloud`, `code`, `wind` and any `vis >= 20000` change no identity.
  - Clouds are not fenced by identity. Cloud pixels stay fenced by the R000B receipt (`reconcileClouds`/`cloudsCurrent`),
    unchanged. `tests/r000b-sky-withdrawal.test.mjs`, `native-weather-withdrawal`, `native-cloud-unresolved` pass.
  - The `tz` element (R002D) and every other element are byte-unchanged.
- **Output neutrality (G1 proof).** The worker job is byte-identical for identical inputs (above) and
  `options.sceneIdentity` is only a label inside the bridge (`physical-sky-bridge.mjs` L8-16), so a refined frame for
  identical inputs is identical. The only behavioural difference in default real-time mode: a weather adoption that
  changes only unconsumed fields no longer withdraws the current refined frame and preview. A change of a consumed
  input (visibility below 20000 m, temperature, source, presence) still withdraws (ES34-03).

### 1.2 ISM-SKY-006 — churn availability (status truth)

States of `availability`: `pending(initial|<invalidation reason>)`, `available(current-frame)`,
`unavailable(rate-throughput)`, **`unavailable(target-churn)`** (new), `pending(disposed)`.

| Event | Guard | Effect |
|---|---|---|
| result dropped: queue `superseded` or `onResult` rejection | not disposed; observed not paused; `job.sceneIdentity === current sceneIdentity`; `job.identity !== current identity` | `churn.drops++`, `churn.inputs` = names of identity elements that moved |
| `churn.drops >= 2` | `availability.reason !== 'rate-throughput'` | `availability = {unavailable, target-churn, drops, last, inputs}` |
| identity change under the same sceneIdentity while `target-churn` | — | epoch++, withdraw; availability kept (no flip back to "pending") |
| acceptance | — | churn cleared; `available` |
| sceneIdentity change, pause, invalid input, dispose | — | churn cleared; normal invalidation availability |

- Reporting bound: at the second dropped submission after onset (ES34-04: first report at <= 4 s simulated wall time in
  the 1200 ms / rate-2 cell).
- `rate-throughput` is a stable-identity condition (same epoch and identity) and is checked first; churn never
  overwrites it (ES34-05, mutant M4).
- Diagnostics: `realSkyState().lifecycle.churn = {drops, inputs}`; `status.last.weather` now reports the consumed
  values `{scope, accepted, source, temperatureC, aerosolTau550}` instead of a copy of unconsumed fields.
- Badge (host, G1 sub-choice): `Sky preview · refinement unavailable while weather keeps changing` when only the weather
  element moved, otherwise `… while sky inputs keep changing`; without a ready preview the prefix is `Refinement`.
  Deviation from the issue's suggested wording ("while preview weather changes"): "preview" is dropped because the
  host cannot distinguish a `timeScale=1` preview from live time; the shorter string is true in both.
- **Live-use result (reproduced).** On `main`, a live weather update that changes only humidity or wind withdraws
  the refined frame and shows "Sky preview · refining…" again until the next refined result is accepted: 1.45 s in
  Firefox and 2.6 s in Chromium in the probe runs (`tools/qa/r0034_stipple_probe.cjs`, adoption step; evidence
  `evidence/R0034/owner-artifact/summary.json` `secondRound`). On this branch the frame is not withdrawn (0 refining
  samples). In ordinary use (source-derived from `src/native/index.html`): the loop polls `fetchWeather` every 30 s
  while visible and a new current record is admitted once the 15-minute current TTL lapses, so about every quarter
  hour; also at boot when the network record replaces the restored cached record a second or two after first paint,
  and after returning from a hidden tab or a configuration change. Each such admission whose consumed values
  (temperature, visibility below 20 km, source, presence) are unchanged withdrew the refined frame on `main`; any
  admission that changes a consumed value still withdraws on the branch, by design.
- Residual (G1 option B/C, not taken): when a consumed input varies continuously and results still arrive in time, the
  refined frame is withdrawn and re-accepted about once per simulated second while availability reads `available`.

### 1.3 ISM-SKY-017 — preview host

States: `constructing -> awaiting-input | preparing | decode-pending | current | composed-by-refined -> disposed`.

- **awaiting-input** (`!sceneIdentity || lat==null || lon==null || paused`): entry (`awaiting === null`) runs the full
  `clear()` once and adds `real-sky-awaiting-input`, recording the cloud receipt returned by that clear's
  `reconcileClouds()` and a Moon-detail mark `{detail, renders, visible}`. Re-entry repeats only effects whose own input
  changed:

  | Effect | Re-entry rule | Why it is safe/needed |
  |---|---|---|
  | `host.reconcileClouds()` | only when `host.cloudsCurrent(recorded receipt)` is false (a new publication) | truth for a changed cloud publication (R000B; R0036 owns the capture-reconcile disposition) |
  | `SalahMoonDetail.clear()` | when the detail owner was replaced, its `renders` changed, it is visible, or it exposes no state | R0033's domain: never skipped when detail state changed |
  | first-paint retirement | while `window.SalahFirstPaint` is non-null | a late head is still retired |
  | `solarPublication.cancel`, value/frame reset, `--native-sun-cloud-mask`, ready class, canvas visibility, status | skipped | already at their withdrawn value; nothing in awaiting-input sets them |

  Leaving: the next `update()` with a scene identity, coordinates and not paused clears `awaiting` and removes the class.
- **dispose()**: single idempotent terminal transition. `if(disposed) return`, retire first paint, drop the catalogue,
  cancel rAF, then run the instance's `owned` releases in reverse (solar publication, `disposed`, canvas removal, and the
  registry slot plus ready class **only while `window.SalahSkyPreview === instance`**). A successor is never touched;
  a second call is a no-op. Construction custody and owner decisions 10.3 and 10.5 are unchanged.

### 1.5 ISM-SKY-019 / ISM-CFG-010 — parse and literal parity

- Camera: first paint uses the native rule (`present but blank -> NaN`); any non-finite camera value installs no head.
- Temporal keys: the native owners are `simTime` and `timeScale` (parity-tested). `simDate` has no native owner but is
  **retained** in the head's exclusion set (G1 sub-choice resolved by retention): keeping it changes nothing, and the
  accepted test `moon/tests/native-lunar-factors.test.cjs` "head producer leaves explicit temporal ownership to
  native without another clock read" requires it. Reconsideration trigger: a native owner starts reading `simDate`
  (then the head must follow it), or the owner asks for `simDate` URLs to get a head (then that test changes with an
  owner decision).
- Reduced motion: `(motion||'') !== 'full' && !!(matchMedia && matchMedia(reduce).matches)`, equal to `isMotionReduced`.
- Identity format: parity-tested against `skySceneIdentity` for Riyadh, London (non-default) and the default zone.
- Geometry census: `tests/real-sky/native-geometry-census.test.mjs` pins the count of `325`/`530` literals per renderer
  module and asserts the `.c` card rule is 325×530 and that no near-miss literal (320–339, 520–539) exists. No shared
  constant (non-goal).

### Genuine negative exits remain available to original assertions

The normal-pair collector previously required every direct/adopted exit to be zero. That would erase legitimate full-fixture refusal and interruption behavior. Full mode therefore preserves a bounded integer natural exit in the range 0–255 and passes the exact code, stdout and stderr back to the unchanged fixture.

A nonzero adopted zombie is admitted only when it is a direct child, already Z, has a natural wait status matching the direct launcher's exit, is named bwrap, and has the matching launch process group/session. Default normal-pair cleanup and terminal admission remain zero-only. A live child is never reaped by the nonblocking natural-reap pass. Signals, survivors, mismatched identities/status, deadlines, incomplete capture and forced cleanup still refuse. The original fixture decides whether each product exit is correct.

### Full observation of unreadable metadata

The original unreadable-profile case holds a read-only parent descriptor before changing its owned metadata inode to mode000. A complete inventory cannot reopen that path as the unprivileged observer. Full-mode inventory therefore uses only that existing, uniquely identified read-only descriptor, verifies device/inode identity and byte count, and retains the mode000 row and content hash. It neither changes modes for collection nor inherits the descriptor into a subject. Missing readers, writable descriptors and replaced inodes refuse. The original fixture restores its inode mode and closes its descriptor in its unchanged `finally` block.

Full inventories retain every directory, regular file and link's metadata; no fixture event, byte, snapshot or capture is excluded. The original fixture's narrower subject-effect snapshots remain its product oracle.

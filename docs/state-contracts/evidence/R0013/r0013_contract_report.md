## Live source defects and falsifiers

### F13-01 — uncertainty becomes false absence (confirmed source)

`install.sh:276-278` returns `0|0|` when metadata is absent. `288-292` catches read/parse exceptions and prints the same record. `317` does so for no grep match. `install.ps1:233-234` initializes false flags; `238-258` skips absent input or catches failures without changing those flags; `260-265` returns a normal object. No Status/Reason exists.

The retained exact-parser probe demonstrates malformed and valid-empty both exit 0/stdout `0|0|`. Its valid legacy and new controls remain useful. This is historical Python-excerpt evidence, not newly executed full Bash or Windows proof.

Repair discriminator: actual functions produce different named knowledge for malformed versus `{"addons":[]}`, and the actual consumer refuses only the unknown target while keeping the healthy known target usable.

### F13-02 — unsupported shape can abort mixed discovery (source-supported inference)

`install.sh:293` calls `data.get` outside the try; `296` assumes every addon supports `.get`; `299` assumes locale supports `.get`. Arrays/scalars/null and malformed addons/locale shapes can throw. `detect_targets` assigns `status="$(firefox_status "$p")"` at 378 under the script's `set -Eeuo pipefail` (17). The exact runtime discriminator is still required, but the source causal path is explicit: unsupported evidence must return a held record rather than stop every peer.

PS also lacks shape admission. A successful JSON conversion with missing/unsupported `addons` can yield a zero-iteration loop and false absence. Test its actual native JSON behavior; do not infer it from Python.

### F13-03 — fallback can lose legacy and certify negative (confirmed source)

Bash `312-317` checks TablissNG before Tabliss, then returns flags with no uncertainty. A file containing both strings follows the new branch; no-hit follows false/false. Test parser-unavailable malformed/empty/new/legacy/both. Conservative legacy evidence must remain a refusal/warning even though complete knowledge is unknown.

### F13-04 — knowledge cannot survive current projections (confirmed source)

Bash `add_target` at 342-346 stores 13 positional fields; Firefox consumption at 378-380 extracts only new/old/matches. All reads at 665, 682, 717, 727 and 735 use that legacy tuple. PS `Get-Targets` at 292-297 copies booleans and matches only. Appending a helper status without migrating those consumers is an incomplete repair.

Raw `hay`/matches at Bash 301-308 can contain pipe/newline bytes, and `add_target` concatenates them into a record. That allows field shifts; it must be prevented at record construction with a declared bounded representation. A delimiter-corrupt profile path must fail safely before effects rather than become a different target. Preserve supported spaces/Unicode/backslashes, the newline-path limitation, structured stdout and Bash3.2 language floor.

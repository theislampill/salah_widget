## Bounds-only zoneDay assessment

Reusing `zoneDay` for conservative ordering evidence is compatible with the accepted inverse boundary if it remains strictly non-authoritative for endpoint precision. The actual profile at lines 917–935 provides per-minute arrays of matching epochs, or `minutes:null` for an unsupported profile. `epochForTzTime` at lines 937–943 alone supplies a precise endpoint after unique-entry and round-trip checks.

The plan correctly rejects wall-minute-only uncertainty tests: during a fold, an apparently elapsed clock may still have a future alternative. Preserve all fold alternatives for bounds. For gap bounds, document exactly which surrounding supported entries are used, retain all their alternatives and use unknown/unbounded ordering if either necessary bound is absent or cannot be justified. Never extrapolate an endpoint from a gap or select one fold member. Conservative equality should block unless a documented tie argument proves the uncertainty immaterial.

Useful independent controls include: a fold clock whose first occurrence is past and second occurrence remains future; the same fold after all alternatives pass; a spring gap before a healthy later target while still potentially relevant; the same gap after its enclosing transition passes; an unresolved event provably later than an ordinary supported earlier target; and an unsupported entire profile. These distinguish honest uncertainty from blanket rejection. Keep expected epochs literal and independent of the selector. I found no reason to introduce a second timezone search or edit the inverse.

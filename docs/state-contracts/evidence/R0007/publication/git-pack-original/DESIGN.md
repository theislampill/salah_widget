## Commission and selection

Root authorized local implementation after the bounded diagnosis in `../publication-second-andon/report.md`. The selected route is a normal Git push of one intermediate commit, followed by connector finalization. REST retries have failed twice; direct job publication of changed workflow files would expand the permission boundary; LFS or splitting the runtime changes the product. All source, controls, disposable fixtures and reports belong in this directory. Existing helper/candidate files remain untouched. No external writes, browser actions, credential export, force option, sibling/main ref effects or acceptance/closure authority are granted.

## Push and credential boundary

The implementation uses the fixed Git URL and one fully qualified refspec, normal fast-forward behavior, and no force, mirror, tag, delete, additional-ref or submodule push options. A private pre-push guard validates Git's advertised old SHA, exact new SHA, exact remote/ref and one update only. Existing pre-push hooks or hooks-path/URL-rewrite/credential configuration cause a fixed refusal; no existing security gate is overwritten or disabled.

An ephemeral askpass script contains no credential. Only the authenticated Git push process environment contains the token under a dedicated variable; builders and ordinary Git children get a scrubbed environment. The script answers only the exact fixed HTTPS repository's username/password prompt, with credential path matching enabled and redirects disabled. No token enters argv, URLs, Git config, files, receipts or raw command logs. Post-push readback uses the scrubbed environment; unavailable unauthenticated readback leaves publication unverified for root, without broadening credential access.

Private intent and guard receipts precede the push. Only one push call is made. Command stdout/stderr are captured in memory and reduced to byte counts/hashes and fixed classifications. Raw error text is never retained. A timeout, rejection or malformed result preserves an uncertain write outcome and stops; independent readback must decide what exists. Root remains the finalizer.

## Meaningful checks and handoff

Use actual disposable bare Git for a successful single-ref push and advanced, rewound, wrong-ref and multiple-update refusals. Check complete intermediate tree/workflow equality and exact six-path finalization; full chain with depth four; refusal when an existing hook/configuration would be displaced; token/config/log exclusion; and uncertain outcome without a second push. Production has no local-remote override; tests patch the module's fixed remote only in their own process.

Run the focused controls and capture raw local producer results. Freeze all packet bytes and hashes for a fresh independent reviewer. Root separately performs the actual target preparation/dry rebuild and any hosted/publication action. No source/body experiment or external push occurs in this implementation lane.

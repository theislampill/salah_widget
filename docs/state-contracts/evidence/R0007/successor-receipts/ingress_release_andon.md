## Causal account and ownership

The established chain is: a fixture-held prayer body remains unresolved; its unchanged product deadline runs; fallback reaches that deadline; abort removes the fixture pending boundary; the subsequently attempted host release fails. The release opportunity was consumed before the font intervention could begin.

The unresolved link is the host interval between the measured loading write and the measured release. The source places the 250 ms sleep and local dispatch/bookkeeping there. The trace does not say when the sleep was entered, when it returned, or how much time elapsed before or after it. Thus “the 250 ms sleep took 7,640 ms,” “Windows overslept,” “the runner was suspended,” “Playwright callbacks blocked it,” and “Firefox rendering caused it” are all stronger than the evidence. Host descheduling is possible; no responsible component is established. A measured sleep wrapper would still measure elapsed residence around the call, including rescheduling delay, rather than identify an operating-system cause by itself.

Local installed Playwright **1.62.0** matches the version recorded in the native run summary. Its synchronous `_sync` method switches to the dispatcher fiber while an API task is pending; `wait_for_timeout` enters that mechanism and sends `waitForTimeout`. Ordinary host `time.sleep` does not enter it. This establishes the different callback-pumping behavior of the two choices. It does **not** establish that callback starvation caused this failure: the held prayer body and its abort timer live in the page fixture, and the original-link CSS is intentionally still held. There is no matching trace of a necessary Python callback prevented from releasing this body. The installed generated API documentation also describes fixed waits as a debugging mechanism with potentially flaky timing; a pumping fixed wait is not a hard deadline guarantee. [Dependency evidence](sandbox:/workspace/scratch/66b3aaff4329/recovery/ingress-release-andon/evidence.json).

The directly demonstrated local defect is **an observation gap covering the only deliberate wait immediately before a deadline-sensitive release**. The repeated excess gap in both arms makes this relevant to the shared harness path, rather than merely an isolated failed assertion. The broader architectural exposure is that a host-thread action sequence controls when a page-held body is released while an independent page deadline continues. That is a source-visible dependency, not proof of a systemic Python, Windows, Playwright or Firefox fault. Shared use of the same sleep branch creates potential wider exposure, but this cord-pull does not justify expanding the case campaign or changing all profiles.

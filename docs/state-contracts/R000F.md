### Defect (base)

- `update()` L221-225 unconditionally refreshes `#code`, assigns `pv.allow` and `pv.src=previewUrl()`;
  `previewUrl()` L216 increments `rev` on every call. There is no issued-identity record.
- Every `fields` control is bound to both `input` and `change` (L253-254), so one committed edit with one value
  assigns `src` twice with different `?r=` and an identical serialized hash (the retained CF05 witness).
- In local mode the serializer omits label/lat/lon, so those edits navigate with an unchanged output.
- Re-clicking the active radio (`setMode` L239), equal-coordinate lookups (`applyCand` L291, `locate` L445,
  `detectArea` L463, `fillNameFromCoords` L340) and whitespace-only `#dfcode` edits (L364) navigate needlessly.
- There is no invalid-draft policy: a cleared or non-numeric portable latitude/longitude is published as a hash
  without coordinates, replaces the last useful preview, and is shown/copied as the export.

### Owner decisions (2026-11-11; confirmed — these were the provisional D1-D3 defaults)

Each decision is one named decision point in `src/native/builder.html` (candidate lines) so it can be changed in
one place.

- **D1 invalid draft** — owner decision, 2026-11-11 (`draftInvalid()` L229): invalid = portable mode with a missing
  or non-numeric required latitude/longitude (the normalized form config yields null). While invalid: keep the last
  valid issued preview, do not regenerate the export (never a silently coordinate-less export), set
  `aria-invalid="true"` on the offending field(s) (`"false"` otherwise) with one short note (`#draftnote` L92,
  `hidden` while valid), and Copy / Install / Open refuse with a readable message (handler check, not `disabled`).
  R001E out-of-range normalization unchanged; local mode keeps its semantics (never invalid for coordinates).
- **D2 identity** — owner decision, 2026-11-11 (`previewIdentity()` L226): no iframe reload when canonical serialized
  output, mode, destination and permission policy are identical (identity = permission policy + base + canonical
  `hash()`; mode is encoded by `local=1` and by the policy). Provenance stays in draft / location-intent state
  (`builderLocation`, pin, tip). A genuinely changed output publishes once. This builder identity is distinct from
  R0003's runtime classifier; no shared config-equality helper exists.
- **D3 Refresh** — owner decision, 2026-11-11 (`#reload` L406): forced refresh — re-issues the last valid issued
  preview (new `?r=`) even when the identity is unchanged; with an invalid draft it re-issues the last valid preview,
  never the invalid draft, and the export is not relabelled current (Copy/Install/Open still refuse). The issue
  receipt (`issued`) is separate from any loaded/rendered frame; nothing observes the latter.

**Attempt 1 (retained: `candidate/firefox-candidate-attempt1-*`).** Firefox failed `changedSelect` (0) and
`radios.enterPortable` (0). Root cause: a driver counting assumption, not a product defect. Attempt 1 counted
`framenavigated` commits. Its own `documentRequests` show both navigations were issued (`?r=1` method=2 and
`?r=9` portable; revisions consumed; the state after Enter read `mode: portable`), but Firefox had not committed
them inside the 1.2 s quiet window, so the next step superseded them and they were never counted. A diagnostic run
reproduced it for `?r=9`/`?r=10` (requested, not committed for 20 s). The product has no Enter handler (the group's
keydown handles arrows only). The mode radios are `<button>` elements, so Enter is native button activation, and
Firefox activated it. Driver changes: count `src` assignments (MutationObserver with `oldValue` chaining), keep
requests and commits as a per-revision ledger, settle until the latest issued preview has committed (20 s cap), judge
issuance (plus the browser's request) in each cell and record commit fate separately, and take viewport rather than
full-page screenshots. Document requests alone were also not enough: on main, Firefox requested only 31 of 34
assignments. On the final runs every candidate assignment was requested and committed in both engines.

### Limits

- The VM ledger counts `src` assignments. The native cells count DOM `src` assignments cross-checked with browser
  requests and commits. Neither proves the widget inside loaded or rendered (no such claim is made).
- Firefox 153 headless sometimes leaves a requested preview document uncommitted until a later navigation, and twice
  crashed the content process during `rapidTyping` in non-retained runs while other browser workloads were running on
  the host (a single retry passed). Neither affects what the product issues.
- `radios.enterActiveLocal` is 0 on main too, so Enter on the already-active radio did not produce an observable
  activation in that step. The Enter contract is shown by `enterPortable` (1 in all four runs).
- Native runs are headless only, on one Windows host; headed/real-device behaviour is not observed.
- `issued` lives in memory for one builder page; a page reload starts a new record (intended).
- If an `src` assignment throws after `allow` was assigned, `allow` reflects the attempted policy until the retry.
- No debounce: rapid typing still issues one navigation per distinct intermediate output.
- Pre-existing, not R000F's: README's frozen-V1 snippet (around L470) is 330×534 and says to "change only src" for
  the current version; the R000F invariant test checks only current-version snippets.

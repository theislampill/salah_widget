### Defect (base)

- `update()` L221-225 unconditionally refreshes `#code`, assigns `pv.allow` and `pv.src=previewUrl()`;
  `previewUrl()` L216 increments `rev` on every call. There is no issued-identity record.
- Every `fields` control is bound to both `input` and `change` (L253-254), so one committed edit with one value
  assigns `src` twice with different `?r=` and an identical serialized hash (the retained CF05 witness).
- In local mode the serializer omits label/lat/lon, so those edits navigate with an unchanged output.
- Re-clicking the active radio (`setMode` L239), equal-coordinate lookups (`applyCand` L291, `locate` L445,
  `detectArea` L463, `fillNameFromCoords` L340) and whitespace-only `#dfcode` edits (L364) navigate needlessly.
- There is no invalid-draft policy: a cleared or non-numeric portable latitude/longitude is published as a hash
  without coordinates, replaces the last useful preview, and is shown/copied as the export.

### Accepted October behaviour preserved, not redone

The 2026-10-09 latest-intent closure
([comment 6073051895](https://github.com/theislampill/salah_widget/issues/15#issuecomment-6073051895), rows O01-O21)
stays as is: separate builder/settings edit owners, `locationEdit`/`srchSeq` invalidation, captured-before-await

boundaries, per-button copy ownership with captured recovery payloads, the radio group (click + arrows; native

after every ownership gate, so dedupe never decides intent.

### Protected invariants

- Builder preview iframe, copy snippet, README and TablissNG preset stay 325×530; `allow="geolocation"` only in
  local mode, assigned before `src`.
- One shared serializer (`SalahConfig.serialize`); no second serializer or comparator; no config-equality helper in
  `config.js` (R0003 owns runtime effect classification; R0026 owns provider admission/outcomes).
- Clamping of out-of-range manual input (R001E) unchanged; `explicitPrefs` (R0010) unchanged.
- No debounce, no disabled form, no new preview framework, no reload scheduler, no `load` observation.
- No new request, no persisted identity (the record is one in-memory object).
- Visual design unchanged when the draft is valid (the new note element is `hidden`).
- Frozen `v1/`; authored source `src/native/builder.html`, root copy regenerated only.

### Provisional policy defaults (pending owner confirmation)

Each default is one named decision point in `src/native/builder.html` so it can be changed in one place.

- **D1 invalid draft** (`draftInvalid()`): invalid = portable mode and the normalized form config yields a null
  latitude or longitude. While invalid: keep the last issued preview, do not regenerate the export, set
  `aria-invalid="true"` on the offending field(s) with one short note (`#draftnote`), and Copy / Install / Open refuse
  with a message (handler check, not `disabled`). Out-of-range clamping unchanged; local mode is never invalid for
  coordinates.
- **D2 identity** (`previewIdentity()`): the real serialized output inputs only (permission policy, base, canonical
  hash). A provenance-only change (same coordinates) updates draft state (`builderLocation`, pin, tip) but issues no
  navigation; target and every serialized field always do.
- **D3 Refresh** (`#reload` handler): re-issues the last issued preview identity (a deliberate user navigation with
  a new `?r=`), never an invalid draft.

## 2. Implemented contract (payload machine)

| Element | Implementation |
|---|---|
| Identity | the regular files of the `github-pages` artifact built from one merge commit |
| Authority | `_config.yml` plus the tree at that commit, built by `ghcr.io/actions/jekyll-build-pages:v1.0.13`. Measurement is authoritative; the git-tree projection is advisory only |
| Instrument | `tools/pages_payload.py` (generalised successor of `tools/verify_r0017_pages_payload.py`, which is frozen to PR 62) |
| Sources | `site` (M2 ci-build `_site`), `tar` / `zip` (M1 artifact stream), `artifact` (read-only API readback of a run's artifact) |
| Verdicts | `within` (measured ≤ bound), `exceeds` (> bound), `inconclusive` (nothing measurable); exit 0 / 1 / 2; instrument error exit 3 |
| Guards | explicit `PayloadError` / `Inconclusive` exceptions, never `assert` (same verdict under `python -O`); bound must be a positive integer |
| Inconclusive | missing or empty `_site`; expired, missing or non-Pages artifact; unsuccessful run; truncated TAR/zip; link members; duplicate paths; size disagreement; receipt for another commit |
| Envelope rule | the zip central directory gives exact `artifact.tar` bytes. Regular-file bytes ≤ TAR − 1024, so the envelope alone can prove `within`. It can never prove `exceeds`: the lower bound rests on an estimated member count and is reported only as `inferredVerdict` |
| Effects | a JSON receipt: counts, regular-file bytes, TAR container bytes, compressed bytes, path-size manifest digest (identical across M1 and M2), top prefixes by size, protected-consumer set digest |
| Stale | a receipt binds the commit and run; `artifact --commit X` on another commit's run is `inconclusive` |
| Diagnostics | `topPrefixesBySize`; `published-diff` and `compare-sites` list removed paths and any protected path removed or resized |

Invariants: (I1) `within` only when measured bytes ≤ bound; (I2) the protected runtime set is
byte-identical across the exclusion change; (I3) no commit-pinned evidence link breaks; (I4) excluded
paths remain in git. Recovery: an over-bound deployment is a delivery incident remediated through
the policy, never by rewriting history.

Protected set (must stay published): `index.html`, `offline.html`, `config.js`, `builder.html`,
`install.sh`, `install.ps1`, `README.md`, `DESIGN.md`, `AGENTS.md`, `OPTICS.md`, `ARCHITECTURE.md`,
`HANDOFF.md`, `tests/widget-fixture.html`, and everything under `v1/`, `presets/`, `real-sky/`,
`moon/` (except `moon/src/`, `moon/tests/`).

### Workflow

`.github/workflows/r002b-pages-payload.yml` (M2) is push-triggered on this branch only. It never runs
on `main` and never deploys. It does five things:

1. Builds the predecessor, current `main` `5a90cc03`, checked out under `_r002b_base`, which Jekyll
   skips.
2. Builds the candidate, both with the pinned builder.
3. Measures both builds.
4. Checks protected byte identity against each build's own source.
5. Diffs the published paths with `compare-sites`.

The declared-change list is `git diff --name-only BASE_SHA GITHUB_SHA`. The step fails closed if
`BASE_SHA` is not the merge base. A protected path may change size only when that list names it, as
`AGENTS.md` does here. An unlisted resize fails. A protected removal fails even when the path is
listed. The run succeeds only if:

- the predecessor's verdict is `within` or `exceeds`;
- the candidate's verdict is `within`;
- only evidence paths disappeared.

The R0017 workflow is untouched. Retiring or re-triggering it, and any PR gate, belong to R002A
(issue 91); serialise with it.

The lower bound subtracts 10,240 bytes of record padding and 2,048 bytes for each of 19,412 estimated
members (twice the projected file count). That covers a header, padding and a GNU long-name record per
member. The archive is GNU tar (`ustar  \0`) with `./` names, with directory members, and is deflated
with a data descriptor. This was checked by inflating the first 1 MiB; that probe was not committed.

Verdict, as the instrument states it: **`inconclusive`, `inferredVerdict: exceeds`**. The deployed
container is 1.93× the bound. Its regular-file bytes are not measured.

**Versus GitHub's documented limit.** "Published GitHub Pages sites may be no larger than 1 GB", and
over-quota sites "may not be able to serve" (GitHub Pages limits page). GitHub currently still builds
and serves the site. Whether or when it would stop is not established.

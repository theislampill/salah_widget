## 2. Storage readout (ISM-CFG-005 row; G2 = a)

`qaState().config.storageAvailable` = `true` iff `window.localStorage.getItem` can be called (read-only); a throw
(`SecurityError` when blocked) gives `false` and `storage.reason`. `storage.basis` states "read-only access check
(getItem); no write probe". `storage.lastWrite` is the last real settings save/clear outcome from `_persistOutcome`
(R0011: `{operation, status, error}`), `storage.lastWriteState` `attempted | not-attempted-in-this-document`.
Semantic change of the compatibility key (G2 a): previously "a write probe succeeded"; now "storage readable". A full
quota therefore reports `true` with the failed write in `lastWrite`, which is the truthful reading the issue requires.
No repository consumer read the key (grep).

## 5. Outcome records and flags

**Machine OUT (ISM-WX-001 attempt-outcome row).** `_wxRequests.<kind>` = `{generation, operationId, attemptId, state,
reason, admission[, adopted]}`. `state` keeps R000D's meaning. `admission` is written by `wxAdmission(op, a, value)` only
into the record this exact attempt wrote (`operationId` and `attemptId` equal); a transport write sets it from
`wxTransportAdmission(state, reason, op, a)`. Vocabulary (DESIGN.md): `pending`, `admitted`, `admitted-track`,
`retained-current`, `early-renewal-miss`, `no-admissible-record`, `provider-error`, `malformed-body`, `zone-rejected`,
`transport-unavailable`, `expired`, `superseded`, `admission-error`; radar adds `malformed-manifest`, `no-frame`, `rejected`.
Review round (advisory A2): an attempt that still owns its request and slot but whose own absolute deadline passed (a
`fetch`/`body`/`image timeout`, or a response that arrives after the deadline) is `expired`; `superseded` is reserved for
an attempt replaced by a newer operation or generation (`wxIneligible(op, a)` decides from `requestEligible(op)` and
`op.attempt === a`). The issue's §5.4 names one outcome "superseded/expired attempt"; both values are distinct from the
other six, so R36-13 still holds. A radar image attempt that cannot begin (only possible when the request is no longer
eligible) now labels the manifest record `superseded` instead of leaving it `pending` (R36-16). The
seven contracted outcomes map to `admitted`, `provider-error`, `no-admissible-record`, `zone-rejected`,
`retained-current`, `malformed-manifest`, `superseded` — pairwise distinct (R36-13). An ineligible (superseded) attempt
may label only its own record, so `state` can still show the last transport stage it reached (`fetch` in R36-11); no
newer attempt's record is touched. R0032's `rejected` is a terminal radar state with its three reasons unchanged.
No admission, retry or freshness decision reads these fields. The generator anchor
`    if(track&&attemptEligible(op,a)){ weatherTrack=track; _renderDirty=true; }` occurs once, byte-identical.

**Acquisition flags (ISM-SKY-031).** `autoDetectStatus`: `idle | pending | ok | failed | superseded` (boot detection
abandoned by a newer generation; written only if still `pending`). `ok`/`failed` unchanged (`r001f-deadline` green;
`v1_browser.py` L199 is a v1 recipe not run here). `config.resetDetect`: Reset's own record `{attempt, status: pending |
ok | failed | superseded | not-needed, source, at}` (`not-needed` with source `configured-site` for the preferLocal
site). `config.geolocationAttempt`: `{attempt, outcome: ok | error | superseded, error, at, superseded}` where
`superseded` is computed at read time (`!_ownsSetLookup(owner)`: an edit, search, Reset, another pin press, closing or
reopening the panel replaced the attempt's lookup owner); `config.geolocationLastErrorCurrent` says whether
`geolocationLastError` (kept, compatibility string) still describes the current intent. The records live in the
settings region so every settings fixture binds them; R0031's accepted mutant anchors
(`  if(!_ownsSetLookup(owner)) return;\n  if(r.ok){`) are byte-identical.

**Override summary (N2, ISM-CFG-011).** `cache.simulated` = at least one effective override; `cache.overrides` lists
them: `simWx` and, only with it, `simTemp`/`simFeels`/`simWind`/`simWindDir`/`simHumid`/`simCloud`/`simPrecip`;
`simTime`; `simMoon` and, only with it, `simWax`; `simMoonAlt` and, only with it, `simMoonH`; `debugOptic` with one of
the six force names (armed; the lunar forces still require moonlight eligibility); an explicit `timeScale`; runtime
clock control (`clockControl`, `SalahClock.set`). `cache.inertOverrides` lists present parameters without effect.
**Deviation from ES36-09's wording:** the issue lists `simMoonH` as a single override that must make `simulated` true.
In source `simMoonH` is read only inside the `simMoonAlt` branch (~L2267), so alone it changes nothing; reporting it as
simulated would be false. It is reported in `inertOverrides` and is simulated together with `simMoonAlt` (R36-06).

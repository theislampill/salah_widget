Owner: the builder script. Functions: `admitReverse`, `fillNameFromCoords`, `setMode` (mode epoch only), and the

| From | Event | Guard | To / effect |

Invariants. (I1) No method change without an admitted `continentCode`; absent, empty or malformed is absence of
evidence. (I2) No request outlives its deadline in effect; the deadline timer is cleared on settlement. (I3) A
superseded lookup (newer edit, newer lookup, or mode change) has no effect. (I4) No new recipient; the body is not
persisted. (I5) The region → method policy is unchanged (D-31-2).

Failure/recovery. Failures stay silent in the tip area (default; no new text). The next eligible coordinate edit is
the retry; switching local → portable schedules no catch-up lookup.

Shape rule. No BigDataCloud reference is cited; the repository evidences `NA`, `EU`, `AS` only. The seven usual
continent codes are an assumption used to choose positive test values. Any well-formed two-upper-case-letter code
other than `NA` (for example `ZZ`) maps to `"4"`, exactly as every non-`NA` value did before.

## 3. Machine GP — settings GPS publication, then the permission diagnostic (ISM-WX-012; D-31-3 = A)

Owner: `_usePrecise` in `src/native/index.html` (called by R0030's pin call site `_usePreciseFromPin`).

| From | Event | Guard | To / effect |
|---|---|---|---|
| idle | pin click | — | `_invalidateSetLocation()`; owner captured; status "Requesting browser location…"; `SalahConfig.geolocate()` (the browser's own permission and consent flow, unchanged) |
| requesting | geolocate settles | owner no longer current | superseded: no write, no diagnostic |
| requesting | admitted fix (`r.ok`) | owner current | **publish at once**: form coordinates, device evidence (accuracy, original fix time — R0023), pin "precise", dirty, status = the pin title ("Browser position · accuracy … · fix … old") |
| requesting | failure (`!r.ok`) | owner current | status reports the failure; location kept; `_geoLastError` set |
| published / failed | — | — | `_geoPermission = "unknown"`; `SalahConfig.permissionState()` started, **never awaited** by the publication |
| diagnostic | settles to a state | owner still current | `_geoPermission` = that state (reporting only: `qaState().config.geolocationPermissionState`) |
| diagnostic | settles | owner superseded | discarded |
| diagnostic | rejects / API absent / throws / never settles | — | stays "unknown"; never retracts or republishes the fix |

Invariants. (G1) Admission precedes publication: the existing `geolocate` admission (coordinates, accuracy,
timestamp) and the lookup owner check run before any write. (G2) Publication never waits on the diagnostic. (G3) The
diagnostic changes only `_geoPermission`; the form, status, pin and dirtiness are written once. (G4) A newer location
intent, close/reopen or Reset discards a late diagnostic. (G5) No new request or recipient: `permissions.query` is
a local browser API, called once per pin click as before. (G6) The status line never flickers: it goes
"Requesting browser location…" → the published outcome and does not change when the diagnostic settles; the
permission state is not shown to the user (it never was).

R0030 interaction. `_usePreciseFromPin` waits for `_usePrecise()` and then ends a pending Reset only if the owned
lookup is still current with new device evidence. Because `_usePrecise` now resolves when the outcome is
published, an adopted fix ends a pending Reset even while the diagnostic never settles (before, the Reset stayed
pending and the fix unpublished); a denied or failed request still leaves the Reset pending. Verified by the VM rows
"R31-07 with R0030 …", R0030's suite and mutation file, and the native `reset-gps-never` cell.

Scene coherence (owner design standard). Behavioural only: no sky, cloud, Moon, solar-optic or weather input is
touched; day/twilight/night and clear/cloudy/precipitating scenes are unaffected. The only presentation it changes
is the settings status line, which now states the true outcome as soon as it is known.

# Returned currentness evidence in hosted research

This source correction belongs to the authorized R002F-A2, R0035, R0040 and
R003F research continuation. It changes recovery of failed pre-dispatch checks,
not product behavior, native predicates, owner policy or acceptance. No registry
verification level is promoted. It is not an audit-controller transition.

## Preserved finding

The complete source assembly at `f3ba20bf8c97baf61388401ab7397739003ff51d`
(tree `733ac10ebdbd4f232f344c4b241c8de34ae6a341`) conservatively refused sealing
when a returned Firefox/WebKit currentness child failed: observation returned 2,

Passive and R002F reached the same outer rethrow by source inspection.

This does not identify the erased sealing-error cause in original run
45748053542. That run has zero artifacts and its cause remains unobserved.

## Narrow transition

For the separate FF/WK diagnostic, passive and R002F tab-hide routes, the observer
requires the exact complete ordered single-lane population and canonical lane
using the actual task and acquired runtime before the optional currentness
child. Existing common, source, preparation and executable custody still apply.
R002F additionally binds its common/build/process receipt and generated-root
locations to the actual task. The original plan and preparation bytes are kept.

The returned subprocess streams are saved as exact bytes in a fresh private
`capture/currentness` directory before success is tested. A JSON process receipt
records their lengths and SHA-256 values beside the actual command, working
directory, bound and result. Decoded text is only a view of those bytes. A
text-only legacy/test record cannot authorize the new recovery path.

Only an exact expected process with an observed integer nonzero exit in 1–125,
or a bounded timeout with a waited integer return, complete retained raw streams
and no reported interruption/error, can raise `ReturnedCurrentnessRefusal`.
The outside coordinator converts that dedicated refusal into the original
planned lane marked `NOT_RUN`, with no invented namespace process. It returns 2
and writes `OBSERVED_WITH_INCOMPLETE_OR_FAILED_LANES`. The unchanged producer
gate can seal this complete failure evidence; no lane is dispatched.

The R002F optional retention callback runs only after its existing generated
checker returns and only after the preceding preparation/source gates. Its
`subprocess.run` timeout interface does not supply an observed waited return
record, so a `TimeoutExpired` remains exceptional in this narrow correction.
No new wait or deadline is introduced. A callback retention error grants no
recovery authority.

Missing/boolean return codes, unsolicited negative signal returns, unknown
completion, interrupted waits, forced or exceptional outer completion, malformed
plans, early source/custody errors and zero-return malformed/mismatching output
retain their existing refusal. The original PSF-specific terminal handling is
unchanged. The producer gate, strict envelope and portable transport are unchanged.

## Evidence and limits

`currentness_return_controls.py` adds 14 bounded source controls. The original
source failed nine of them. The first corrected run exposed a missing synthetic
acquisition sidecar in the new FF/WK fixture; that failure was retained and the
fixture was completed without changing the production gate. The controls run the
real observer, canonical planner and sealing-admission functions with explicit
synthetic native prerequisites, and preserve undecodable bytes from actual small
subprocesses. They are not hosted native evidence or proof of containment of an
arbitrary descendant. The existing trusted immutable checkout/task custody
model remains in force. The complete successor still needs independent exact-tree
review and current preparation before activation.

This change does not alter any sky or weather presentation, capture samples,
pixel thresholds, original capture waits, scientific predicate or human gate.

## 1. Implemented contract (ISM-BLD-007)

**Entry points (consumed by R002A, issue 91).**

| Item | Value |
|---|---|
| Runner | `python tools/cp9/run_native_regressions.py --output <new dir> [--select names…] [--timeout s]` |
| Population manifest | `tests/regression-population.json`, schema `salah-regression-population/1` |
| Ledger | `tests/expected-failures.json`, schema `salah-expected-failures/1` |
| Receipt | `<dir>/results.json`, schema `salah-native-regressions/2` plus `population`, `ledger`, `setupErrors`, `verdict`, and per-command `ledger` |
| Verdict string | `results.json` `verdict`: `PASS`, `PASS_WITH_DECLARED_FAILURES (n)`, `FAIL` or `INCOMPLETE`; the runner also prints `VERDICT <string>` |
| Exit code | `0` PASS; `3` PASS_WITH_DECLARED_FAILURES; `1` FAIL/INCOMPLETE; `2` argument error |

A certificate quotes the verdict string verbatim. `PASS_WITH_DECLARED_FAILURES (n)` is never reported as PASS.

**Population.** The runner's R0017 selection (`native-runner-contract`, `native-test-glob`, the 27 `NAMED`
instruments) plus every command in the manifest: the `.test.mjs` glob, 17 further direct instruments,
direct-mode runs of the two `SNAPSHOT_ONLY` instruments, the `tools/qa` sanitize unit check
(mutation suites, `r001d-diagnostics`, `rlgwo-docs-contract`, `v1_storage`, …), `tests/real-sky` `.mjs` and
`.cjs` suites, `native-head-handoff`, `moon/tests`, every headless Python unittest group (one command per
file) and the vendor scientific suite through `tools/cp9/run_scientific_regressions.py`. Each command has an
argv, a terminal protocol, its inputs and the files it covers. Imported modules and fixtures are listed as
`modules`; instruments that cannot run headless and effect-free here are registered `exclusions`, each with a
reason and its own qualification owner (installer platform suites, Python-Playwright browser harnesses,
`install-builder.cjs`, the POSIX-only namespace probe, the `tools/test_moon.py` wrapper, and the R0037 native
browser recipe, recorded with its argv and capture protocol). `nativeTestGlob` pins the members of the
`native-test-glob` command so a deleted or unlisted `tests/*.test.cjs` is a setup error. `protocols` overrides a NAMED command's terminal protocol (only
`r0022-baseline-balance`, whose output is case lines plus a diagnostic object).

**Terminal protocols.** R0017's `auto` (TAP, `json-results`, `json-summary`) and `unittest`, plus:
`case-lines` (PASS/DETECTED/FAIL lines; complete only when the distinct case count equals the declared
`expectedCases`), `json-lines` (one JSON case per line and a `summary` whose counts must agree),
`json-cases` (`{allPassed, cases[]}`), `unittest-cases` (verbose unittest; failure identities from the
FAIL/ERROR blocks, skips from the verbose lines; complete only when they equal the terminal counts) and
`scientific` (the scientific runner's `results.json` and its three logs; the oracle must be unchanged).

**States.** Per command: `PASS` | `FAIL` | `INCOMPLETE` | `PASS_WITH_DECLARED_FAILURES` | `HISTORICAL_EXCLUDED`;
registered exclusions are listed in the receipt, not executed. Per case: pass | fail | expected-fail |
unexpected-pass | not-executed. Ledger entry: `active` | `retired` (kept for history, never matched).

**Ledger entry.** Required fields: `id`, `status`, `kind` (`case-fail` | `case-not-executed` |
`command-incomplete`), `command`, exact `case` (null only for `command-incomplete`), exact `messagePrefix`,
`firstRed`, `causeClass` (`harness-gap` | `stale-pin` | `stale-expectation-vs-accepted-contract` |
`unadopted-contract` | `undetermined`), `evidence`, `owner` (`Rxxxx` or `pending-owner-decision`),
`disposition`, `trigger`. Optional: `discriminator` (required for `undetermined`), `condition` (one probed host
fact, currently `symlink-unavailable`), `notes`, `retiredBy`. No wildcards, regexes or counts.

**Transitions (owner: `adjudicate()` in the runner, after each terminal command).**

| Event | Guard | Effect |
|---|---|---|
| failing case | one active entry of kind `case-fail`, same command and case, message starts with `messagePrefix` | expected-fail |
| failing case | no entry, or a different message prefix | unexpected failure → command `FAIL` |
| unexecuted case (TODO/SKIP, `SKIP_*`, unittest skip) | exact `case-not-executed` entry | declared not-executed |
| unexecuted case | no entry | command `INCOMPLETE` |
| active entry | its case passed | unexpected-pass → `FAIL` (retire the entry in the same change) |
| active entry | its case absent from a complete output | not-executed → `FAIL` |
| abort, timeout, unparsed or setup failure | — | case entries are not adjudicated; command stays `FAIL`/`INCOMPLETE` |
| incomplete command | `command-incomplete` entry whose `messagePrefix` equals a whole log line | declared incompletion |
| all failures declared, ordinary failure exit (1, or 0 when only unexecuted cases are declared) | — | `PASS_WITH_DECLARED_FAILURES` |

**Guards (setup errors; the run is `INCOMPLETE`, never PASS).** Missing manifest in a root that carries the
runner; malformed or duplicate manifest entries; an instrument-shaped file (`tests/*.cjs|js|mjs|py`,
`tests/**/*.test.cjs|.test.mjs|_test.py|*.cjs`, `moon/tests/*.test.cjs|*.py`, `tools/**/test_*.py`) that is neither selected, a
module nor an exclusion; a module/exclusion path that does not exist; a malformed, duplicated, wildcard or
unknown-cause ledger entry; an `undetermined` entry without a discriminator; an entry naming a command
outside the population or a registered exclusion. Isolated fixture roots without the manifest keep R0017
behaviour unchanged (all 42 R0017 runner controls pass unmodified).

**Effects.** Receipts only, in the new caller-supplied directory. Every child receives `TMP`, `TEMP` and
`TMPDIR` inside `<receipt>/tmp/<command>`; the two mutation suites that default to the OS temporary directory
receive explicit parents there (`r0009-date-mutations` argv[3], `r0025-mutations --output-dir=`).

**Invariants.** (I1) An entry cannot hide a different failure in the same instrument (exact name and
message). (I2) Removing entries only exposes failures. (I3) Entries carry evidence; `undetermined` needs a
discriminator. (I4) The ledger never changes a test expectation: repairs happen in the test and retire the
entry.

**Recovery.** A stale ledger fails loudly (unexpected-pass / not-executed). Rollback removes the ledger and
manifest together with the runner change and returns to prose comparison — a disclosed loss of signal, never a
silent PASS.

**Obligation for later work orders (manifest maintenance).** The manifest is hand-edited reviewed data. A
change that adds, renames or removes an instrument edits `tests/regression-population.json` in the same commit:

| Change | Edit |
|---|---|
| new or renamed `tests/*.test.cjs` | add or rename it in `nativeTestGlob` (the glob command itself is derived from disk) |
| new directly run instrument (`tests/*.cjs`, `tests/**/*.test.mjs`, `*_test.py`, `tests/*.py`, `moon/tests/*`, `tools/**/test_*.py`) | add a `commands` entry: `name`, `argv` (`{python}`, `{receipt}` placeholders), `protocol`, `inputs`, `covers`, and `expectedCases` for `case-lines` |
| imported helper or fixture | add a `modules` entry with a reason |
| browser/native recipe or non-headless suite | add an `exclusions` entry with a reason and an owner; a native recipe also records `recipe` (`argv`, `protocol`) |
| removed or renamed instrument | delete or rename its entry and any `tests/expected-failures.json` entry naming it |

Verify registration with `python tools/cp9/run_native_regressions.py --output <new dir> --select native-runner-contract`.
The census always covers the whole tree regardless of `--select`, so any `setupErrors` in the receipt (unregistered
instrument, missing glob member, missing path) make the verdict INCOMPLETE. A merge that brings in another work
order's instruments is verified the same way before it is published.

## 1. Machine RN — current-weather renewal (ISM-WX-001 / ISM-WX-003)

**Scope.** Live real-time lane only (`SIM.wx==null && !ADVANCING && !_clockPreview`), one runtime generation and
weather target.

**Owners.** Freshness: `weatherEligibility` (unchanged). Request permission: `retryGate` (order unchanged:
SIM → target → busy → shortcut → spacing; one preview-lane shortcut line added for §3, live lane untouched).
Renewal timing: the pure `weatherRenewal(now, record)` next to `retryGate`. Request: `fetchWeather` (unchanged)
through `renewWeather()`, which the existing loop tick calls as
`else runRenderStage("weather-renewal",()=>renewWeather())` — the `else` of the unchanged ~30 s poll line, in
its own contained stage; R002C's stage order is otherwise unchanged.

**States** (`qaState().wxTruth.retry.renewal.stage`):

| Stage | Condition |
|---|---|
| `suppressed-by-mode` | SIM, fast-forward or clock preview |
| `no-record` | no current record, or one belonging to another target generation |
| `contract-fallback` | `currentIntervalSec !== 900` or `currentValidAt` not on the 15-minute UTC grid (provider contract assumed here no longer holds): baseline poll only |
| `disagreement-fallback` | the record was future (`currentValidAt > retrievedAt`) or already expired (`retrievedAt − currentValidAt > TTL`) when received — clock disagreement or publication lag: baseline poll only |
| `not-due` | `now < currentValidAt + TTL + m` (or the record is still eligible) |
| `due` | step ended + m, no renewal issued yet for this step/generation |
| `requested` | the renewal request for this step is in flight |
| `early-renewal-miss` | the renewal answer was admitted and valid but its step is not after the held record's: not adopted, not cached, no receipt; the spacing that attempt opened is restored to its previous value, so `retryGate` answers for the next ordinary poll exactly as if the renewal had not happened; not due again for this step (one exemption per step) |
| `settled-not-advanced` | the renewal failed (HTTP, timeout, cancel, malformed or rejected response): R000D's 60 s spacing stays; due again when `retryGate` opens |

**Amended R000D rule (owner authorisation, option D).** *A renewal request whose response is admitted and valid but
whose current step is not after the held record's is an early-renewal miss. It is not an acquisition and not a
failure; the 60 s spacing it opened is restored, so the next ordinary scheduled poll proceeds. At most one per
provider step. All other attempts keep R000D's 60 s elapsed spacing.* Implemented in `fetchWeather(renewal)`: the
attempt's previous spacing record is kept (`priorSpacing`) and restored only for a classified miss and only while
the spacing record is still this attempt's own; the miss is never adopted (`!miss` in the adoption guard), so
nothing stale is presented, cached or counted as `lastWxAt`. If the ordinary poll then also gets the old step, that
is an ordinary attempt (adopted as expired-at-receipt, R000D spacing, `disagreement-fallback` — exactly main). A
response with the next step replaces the record: `not-due` for the new step (`settled-advanced`).

**Guards and invariants.** (I1) `due` requires `now ≥ currentValidAt + 900 000 + m` with m ≥ 0 and the record
ineligible, so renewal never requests while the record is selected and never extends freshness; the withdrawal on
the first frame after `currentValidAt + TTL` is unchanged (R000B order). (I2) every request still passes
`retryGate`: ≤ 1 weather request per 60 s elapsed; one renewal request per step in healthy operation. (I3) no
timer, interval or clock manager: evaluation happens only in the existing visible loop tick (hidden → no frames →
no requests; resume → the ordinary poll, one request). (I4) real time never substitutes forecast. (I5) renewal
does not touch cloud population, seed or motion.

**Events.** Generation/target change: the old `_wxRenewal` no longer matches (`step` + `generation`), a late body
is rejected by `attemptEligible` (unchanged N03). A forward wall jump across several steps: one due evaluation,
one request (busy/spacing). Backward jump: the record becomes future/ineligible exactly as before.

**Diagnostics** (pure read, R0036 audits purity later): `stage`, `reason`, `marginMs`, `marginBasis`
("assumed (owner decision: option D, 3 s); adequacy against the live provider unverified"), `step`, `dueAt`, `clockAgreement`
(`agreeing` / `disagreeing-future` / `disagreeing-expired-at-receipt`), `lastRequestStep`, `lastOutcome`.

**Hard limit (issue B.2).** The gap cannot be zero: the next step exists only from the boundary. Measured result
under the stub: gap ≈ min(poll phase, m) + latency when lag/skew < m; when lag or device-ahead skew exceeds m the
first answer repeats the old step (early-renewal miss) and the ordinary poll then gives exactly main's gap
(§1a: demonstrated never worse than main over the skew/lag × phase matrix).

## 1a. Margin hazard — lag/skew above m (quantified before the decision; removed by option D)

Model (the same rules the Node suites exercise; request latency zero, add it to every figure). L = provider
publication lag plus device-clock lead over the provider (the time after the device-clock boundary B at which the
next step is first served). The ordinary poll falls at B + p, p uniform over (0, 30] s, then every 30 s. A request
that returns the old step is adopted (old record no longer eligible) and starts R000D's 60 s spacing.

- **main:** gap = p when p ≥ L, otherwise p + 60.
- **R002F:** when p ≤ m the poll comes first and behaves exactly as main. When p > m the renewal fires at m:
  gap = m when L ≤ m; otherwise the old step comes back at m, the record is then expired-at-receipt (not renewed
  again) and the spacing opened at m blocks the polls at p and p + 30, so gap = p + 60.
- R002F is therefore worse than main exactly when **m < L ≤ p** (by 60 s), and never worse otherwise.

| 0 | 15.0 | 2.9 | 0 % | 8.3 | 0 % |
| 1 | 17.0 | 4.8 | 0 % | 10.3 | 0 % |
| 2 | 19.0 | 6.8 | 0 % | 12.3 | 0 % |
| 3 | 21.0 | 8.8 | 0 % | 14.3 | 0 % |

(Computed over 30 000 evenly spaced phases. L = 0 includes the ≤ 1.1 s publication lag R000B recorded at one live
boundary; ordinary NTP-synced devices are within about a second.)

**What the margin does (D-2F-7 range 0–10 s).** A larger m costs about m − 3 s in the common case (L ≤ 3 s:
mean ≈ m − ε instead of ≈ 3 s, still below main's 15–21 s) and removes the regression for every L ≤ m. m = 0 makes
any positive L a regression in (L, 30]. No m inside 0–10 s removes it for 10 s < L < 30 s.

**Can the regression be removed without amending R000D?** (Pre-decision analysis.) No, not completely. The loss comes from one fact: any
attempt made before the poll at p that returns the old step starts R000D's 60 s spacing, which then blocks the poll
at p that main would have used successfully. Avoiding that needs the renewal attempt to be exempt from (or to
shorten) the spacing — an R000D change, which D-2F-2 (No) excludes. Scheduling the renewal later does not help
unless it is at or after p (then it is the poll). So the code is left as delivered and the options are for the owner:

| Option | Common case (L ≤ 3 s) | Skewed case | Contract change |
|---|---|---|---|
| A keep m = 3 s (delivered) | ≈ 3–9 s | 3 < L < 30: worse than main for phases ≥ L (+60 s) | none |
| B m = 10 s | ≈ 8–14 s | 10 < L < 30 only | D-2F-7 value |
| C A or B, plus: after one not-advanced renewal in a document, stop renewing (main's cadence) | as A/B | at most one worse boundary per document | small, inside RN; still worse once |
| D renewal response carrying the same step does not open the 60 s spacing (next ordinary poll proceeds) | as A/B | never worse than main | amends R000D (D-2F-2 Yes) |

Recommendation given before the decision: B (or B + C), D only if the owner amends R000D. **The owner chose D with
m = 3 s** and authorised the R000D amendment (issue 96, 2026-11-13).

## 3. Machine PV — preview substitution range (ISM-WX-009, range only; D-2F-4 A)

`wxTrackRange(ms)` → `null` (no usable track for this target) / `before-first` / `inside` (first and last hourly
point inclusive) / `after-last`. In explicit preview `syncWeather` installs, outside the track, an explicit
marker `{code:null, previewRange, src:"forecast", units, target, provider, product}` (never the previous object);
`selectedWeather`'s preview branch never presents a record with `previewRange`. Inside the track the substitute
is `wxAt`'s interpolation, unchanged (`wxAt` itself still clamps; its accepted r000c control is untouched).

- Live return: the marker keeps `src:"forecast"`, so `SalahClock.set({live:true})` reloads the cache and requests
  in the same call (gate permitting) — no guard change (R2F-12a).
- Frozen preview (`rate:0`): the loop still polls. A live record fetched meanwhile may sit in `weather` between
  frames (and pure `qaState` reads may report it there), but the next frame's render re-substitutes the marker
  before any header/cloud/effects stage, so no frame presents it (R2F-12b).
- Request behaviour: one added `retryGate` line keeps the preview-lane shortcut exactly as before (held preview
  object + track + fresh `lastWxAt`), so preview request counts are unchanged.
- Residuals: the value at the last hourly point stays presented until the next render (< 1 simulated second); a
  preview without any track keeps the accepted R0024 behaviour (the current record is shown in the preview lane —
  rejecting it would change accepted R0024 assertions the issue does not name). The track's retrieval age is not a
  validity bound. Identity churn of the substitute stays with R0034.

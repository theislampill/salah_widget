## Command transition and effect order

| Event | Guard | State and ordered effects | Invalid/recovery path |
|---|---|---|---|
| Select | Known unique command names; explicit selection nonempty | Freeze plan before inspecting outcomes; retain default old 28 identities plus the evaluator control command | Invalid selection fails invocation; empty native glob produces incomplete setup, never implicit Node discovery |
| Check setup | Named current paths and exact historical objects available | Record input hashes/blob identities before launch | Missing input gives INCOMPLETE with locator and no child launch; no current-source substitution |
| Launch | Setup READY and no prior infrastructure stop | Append `running`, capture `started_elapsed`, open raw log, start argv in specified root | Launch error retains cause, elapsed measurement, sentinel exit 127 and no invented observed return code |
| Exit | `subprocess.run` returned | Freeze actual return code and elapsed seconds before parsing | Nonzero exit cannot be erased by a PASS-shaped log |
| Timeout / cancel | Host boundary is observed | Retain partial log, elapsed duration, `timed-out` or `cancelled`; stop later launches | Timeout sentinel 124 / cancellation sentinel 130; `execution.returnCode` remains null |
| Classify | Known complete output protocol | Attach descriptive counts and execution proof without changing process facts | Unknown, malformed, contradictory or incomplete output stays INCOMPLETE; catchable classification cancellation preserves prior exit and stops later launches |
| Reconcile exclusions | Exact observation and command scope | Retain raw exclusion and structured residual; do not add it to pass counts | Unknown skips or unproved replacement observations keep command INCOMPLETE |
| Terminalize | Exactly one terminal per planned member | Append `output-classified`, `terminal`; persist receipt after each result | Remaining commands after infrastructure stop receive not-started INCOMPLETE records |
| Summarize | Records equal immutable plan by ordered identity and argv | FAIL dominates INCOMPLETE; PASS requires all applicable selected obligations proved | Missing/duplicate records or invalid terminal state raise an invariant error; a partial RUNNING receipt is never success |
| Bind source | Source census unchanged through invocation | Retain starting HEAD/tree plus working overlay and final unchanged flag | Source drift/unavailability invalidates acceptance; it does not erase an already observed FAIL |
| Retry | New invocation/output directory | New UUID and logs; previous attempt retained byte for byte | Existing directory is refused; no in-place overwrite of red evidence |

The lifecycle is `selected → setup-checked → running → exited | timed-out |
launch-failed | cancelled → output-classified → terminal`. No-launch and explicit
disposition paths omit `running` and retain their reason. Forced process death,
unrecoverable filesystem failure, or repeated interruption can prevent persistence;
the resulting RUNNING/partial receipt is visibly incomplete, never proof of success.

## Output and compatibility contract

Schema: `salah-native-regressions/2`. Existing keys `commands`, command `name`,
`command`, `exitCode`, `seconds`, `counts`, `log`, `explicitExclusions`, aggregate
`status`, and `notRunHistorical` remain. `seconds` is monotonic wall duration in
seconds, including launch/wait overhead; child TAP `duration_ms` is a different
measurement. Neither figure is a cross-platform performance qualification.

New fields include `plannedCommands`, `identity`, `setup`, `execution`, `output`,
`lifecycle`, `caseExclusions`, `reason`, `sourceUnchanged` and an identity error
when needed. For actual exits, `execution.returnCode` is the observed code.
Compatibility sentinels on timeout/launch/cancel are distinguishable from it.

Accepted output shapes are the actual repository protocols:

- Node TAP: complete single totals, ordered top-level plan, observed case/suite
  population, matching pass/failure/cancel/skip/TODO counts. Nested Node suites are
  distinguished from leaf tests; a zero plan or a skipped case cannot invent a pass.
- A complete terminal JSON `results` array with unique named cases and recognized
  `status`/`result`; conflicting aliases or duplicate object keys are refused.
- PASS/FAIL case lines plus a complete matching JSON count summary. Lines and totals
  must agree; supported `pass`/`passed` or `fail`/`failed` aliases cannot contradict.
- The deadline caller's `realElapsedMs`/`instrument` diagnostic and metadata caller's
  exact older-consumer diagnostic may precede that final summary. They are metadata,
  not earlier verdicts; malformed objects and prior result envelopes are still refused.
- The evaluator's own positive standard-library unittest completion, with nonzero
  process exit remaining independently authoritative.

Leading JSON and a final column-zero JSON object after text are admitted. The parser
does not salvage a nested/later success object from a broken earlier envelope.
Outer FAIL cannot be weakened by inner counts; outer INCOMPLETE cannot hide an
observed assertion failure. A `SETUP_INCOMPLETE` exception is setup evidence, and
mixed setup plus real assertion failures retain both facts.

CLI: 0 for PASS, 1 for FAIL/INCOMPLETE, 2 for invalid invocation or output setup.
Use a fresh output directory outside the checkout, especially when a parent
qualification process writes adjacent logs. A working-source overlay binds real
modified/untracked bytes; it is not intended to ignore arbitrary changing files.
Python 3.11+ supplies `hashlib.file_digest`; no package install is required.

## Adapter admission and preserved behavior

The adapter identifies the native owner's actual configuration/model/render/boot
anchors once, validates approved script attributes/order and prerequisite hashes,
and returns only the intended native body unchanged. Current documents cannot
become historical layouts merely by losing startup scripts. Genuine retained
historical inputs keep their explicitly admitted profile. Unknown layouts require
source review and a setup failure; a convenient first `<script>` is never enough.
The current authored `src/native/index.html` has its own exact source-bound profile
for the existing hotfix caller. Its two-script shape is not a generic fallback for
a damaged generated entry. Rebind that authored identity after reviewing an actual
authored-source change; never learn the allowed identity from an untrusted input.

The browser wrapper loads the shared contract before analyzing the product entry.
Its controlled storage/clock/fetch shim is still inserted before product parsing.
`r0017-transport.cjs` follows that declared helper and records its identity. Node
fixtures reuse the same admission logic; none installs product code into the
owner's browser or clears real storage.

Only fixture plumbing changes: source discovery, current initial-document
declarations, host-turn delivery and the actual combined particle selector.
Preferences/storage tests await the already-existing boot boundary. Storage's
terrain double records the current `finishInitialDocument` handoff and adds a
retirement assertion. Product assertion values are retained. The adapter tests
must admit valid product-guard mutants far enough to fail their behavior assertion;
refusing the mutant as malformed setup does not satisfy that obligation.

## Preservation and rollback

The prior [smoke closure certificate](https://github.com/theislampill/salah_widget/issues/23#issuecomment-6181111816)
and [readback](https://github.com/theislampill/salah_widget/issues/23#issuecomment-6181220586)

No runtime/scientific source, generated entry, Moon artifact, installer or Pages
workflow is changed by this increment. Generated output is therefore not rebuilt;
Git protected-path equality and the frozen-V1 verifier establish the preservation
boundary. C24's `.github/workflows/r0017-pages-payload.yml` and
`tools/verify_r0017_pages_payload.py` remain untouched; no CI/deployment claim follows.

Before merge, discard/revert only this dedicated candidate branch as authorized by
the owner. After a separately approved merge, an owner-approved revert must keep
`native-script-contract.js`, its Node/browser consumers and their assertions coherent.
Never roll back to a false-green missing-execution state. The independently correct
monotonic duration/lifecycle repair can be retained if an adapter must be reverted;
that adapter's scope then stays INCOMPLETE and gets a new invocation receipt.

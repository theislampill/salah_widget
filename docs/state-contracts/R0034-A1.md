# R0034-A1 — Daytime aureole decomposition on the worker lattice (candidate contract)

Amends R0034 (issue 101). Status: **isolated candidate, not merged, not owner-approved.** Merge requires the owner's
visual approval of the before/after evidence (`docs/state-contracts/evidence/R0034/A1/`) and an independent
exact-candidate review. `wholeContractComplete: false`.

Base: `origin/main` `516d8cc8a79ff2b4e3f24fd77f00d962d28278c9`.

## Defect

`real-sky/native-host.mjs` `accept()` (main L219) chose the lattice for the host-side display decomposition as
`altDeg < -3 ? [⌈325/step⌉, ⌈530/step⌉] : [24,40]`. The worker samples the background on
`[⌈325/step⌉, ⌈530/step⌉]` (step 8 → 41×67, `real-sky/core/src/physical-sky-renderer.mjs` L47). In daylight
`nativeSkyPresentation` (`real-sky/native-preview.mjs` L132+) computes `shown = source + aureole·(gain − 1)` with
`source` on 41×67 and `aureole` (solar aerosol share) on 24×40. Near the physical Sun `gain ≈ 0` above 20° solar
altitude, so the display carries `interp₄₁ₓ₆₇(f) − interp₂₄ₓ₄₀(f_aer)`: soft vertical and horizontal ridges around
the physical Sun's camera position (the owner-reported bars under issue 101). The comment above the line already
required the worker's nodes; only the night/twilight branch honoured it. The line was introduced in `dbc0387b`
(2026-10-07) with no recorded rationale.

## Change

One authored expression in `real-sky/native-host.mjs`: `grid=[Math.ceil(325/step),Math.ceil(530/step)]` at every
solar altitude handled by the host decomposition (−20° and above; deep night keeps the worker-prepared lunar
display and runs no host decomposition), plus a four-line comment. Generated `real-sky/native-sky.js`,
`offline.html`, `GENERATED.json` regenerated by `python tools/build_native.py` (twice; second run clean).
No core, vendor, encoder, CSS, worker or preview change.

## Producer contract after the change

- Inputs: accepted worker raster (`skyBackgroundLinear` on the worker lattice), `physicalState`, `atmosphere`,
  `view`, the measured corner anchor.
- Invariant: **the removed aureole and the field it is removed from are sampled on the same lattice at every solar
  altitude** (worker lattice `[⌈325/step⌉, ⌈530/step⌉]`).
- Composition order unchanged: worker raster → host fields (`nativeAtmosphereFields`) → `nativeSkyPresentation` →
  `compose()` (clouds/Moon/calendar) → `encodeNativeDisplay`.
- Failure behaviour unchanged (same throw sites, same withdrawal path).
- Preview unchanged (its own background and aureole share [24,40], or [12,20] when fast; they cancel).
- Performance: `tools/qa/r0034_a1_bench.mjs` (node, owner scene, 15 runs): decomposition+presentation median
  130.3 → 149.9 ms (p90 165.3 → 179.2 ms), nodes 1025 → 2856. Worker message unchanged (no worker change).
  Declared bound: ≤ +50 ms median on this host; observed +19.6 ms.

  executes the authored `accept()` body in a VM. (1) every altitude −19.99..60 at steps 8 and 6 requests the worker
  lattice (step 6 rejects a hard-coded 41×67); (2) deep night requests no decomposition; (3) owner scene pixel
  witness: lattice ridge ≤ 1.5 levels. RED on main (commit `0bed3480`): (1) fails at alt 60/step 8; (3) ridge 10.11.
  GREEN on the candidate: ridge 0.96 (VM matrix) / all three pass. The restored conditional is the main source
  itself, so the RED run is the mutation control.
- Rebound: `tests/real-sky/native-preview.test.mjs` "preview and refined atmosphere share daylight identity within
  a display-code bound" built its "refined" side with the default [24,40] lattice, which no longer represents the
  shipped refined path. It now passes the worker lattice (`backgroundStepCss`), as `accept()` does. Semantic reason:
  the test compares preview against the refined presentation; it must use the refined presentation's lattice. Its
  bound (p99 ≤ 8 codes) is unchanged and still passes.
- No other test pins daytime refined bytes (all 378 real-sky mjs tests pass unchanged).

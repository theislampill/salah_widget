## 1. Implemented contract

### 1.1 No-timetable optic withdrawal (R3A-01, CI-07)

- **Owner.** `paintCelestialWithoutTimetable` (`src/native/index.html`), the existing scene owner that already zeroes
  the prior-scene solar optics (`--sunhalo`, `--sundogs`, `--sunpillar`) and lunar optics in the no-timetable path. Its
  key list now also holds `--ray` and `--anticrep`. No new mechanism; one list widened.
- **Caller and guard.** One caller: `render()`, branch `!M || !prayerPublished` (`runRenderStage("celestial", …)`). A
  rendered timetable never reaches it (test R3A-01 "a rendered timetable never enters…").
- **Corrected fact.** The registry said the two values persist "until the next per-frame reconcile". On `516d8cc8`
  the same branch first runs stage `weather-withdrawal`, whose `withdrawWeatherEffects` key list already includes
  `--ray`/`--anticrep`, in the same synchronous turn. The real residual was narrower: when that stage fails on both
  bounded attempts, the celestial stage still ran and left earlier-scene shaft values. That is now closed.
- **Classification.** A demonstrated implementation defect **only under an injected fault**: the tests make the
  withdrawal stage throw (a `--rain-op` style write throws). It was not observed in any natural scene, and no natural
  path that makes that stage throw is known.
- **Invariants.** In a withdrawn (no-timetable) render every write to `--ray`, `--anticrep`, `--sunhalo`, `--sundogs`,
  `--sunpillar` is 0, so no transient false light; the painter's "0" writes are exactly those five plus the three lunar
  optics, and its solar presentation (`--sunvx/--sunvy/--sunray/--sunlift/--sundisc`) keeps its computed values; a
  healthy timetable scene publishes its computed `--ray`/`--anticrep` (§3).
- **Failure/recovery.** If the effects withdrawal throws, the painter still withdraws the optics; the stage faults
  remain recorded by `runRenderStage` as before.

### Two protocol details for review

1. The specified reference switches to `unboosted-v5-01` with `lift: 0`. The normal calendar profile has lift 0.003. Both the host's initial-presentation guard and `createInitialMoon` refuse the reference profile. The runtime explicitly identifies it as worker-only. Thus the specified reference measures a separately rendered, unboosted surface at the same altitude. An initial calendar frame can be compared to that identified worker reference after it settles. A tier-matched initial reference would require a different protocol. See `moon/src/moon-native.mjs` 29, 222, 447, 469 and `moon/src/moon-initial.mjs` 37.
2. T preserves scalar gain and, up to Float32 rounding, each receiver's Y. It changes colour even in the near-new cells where the gain cannot increase. In the 540-square initial waxing 0.01 surface, B0 and all three proposals have gain 1. Applying T changes at least one straight sRGB channel at 187,839 compact receiver locations (184,927 on the parent) versus the same rule without T. F-GAIN records this comparison for every rule and phase. These codes precede area filtering and the card composite. The question for G-F2 is how D1's B0-byte requirement is to be applied to a separately waived colour cue. The numerical record chooses no exemption and estimates no native ΔE*ab.

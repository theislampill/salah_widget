## Surface results

F-GAIN evaluates all nine fractions in both senses. The canonical terrain engine uses the admitted DEM, colour and WASM. The 160- and 540-receiver rasters use the same phase, orientation and display profile. The initial receiver uses its shipped 540-square field. For each surface the calculator independently reconstructs B0, compares every Float32 byte against production `calendarProxy`, and evaluates B1c, B4 and B6 in the order printed in the issue. The 99.5th percentile for B4 uses linear interpolation over the complete raster, including zero-coverage pixels.

The cheap recurring test uses 4×16 finite-source samples. The longer run uses production `adaptiveRender` and records the final quality status for every cell. Each report identifies its source and asset hashes, phase sense, surface identity, gain and calendar-token hash. All 36 adaptive cells reached `empirical-adaptive`. The initial report additionally checks each of its 18 published calendar arrays against the independent reconstruction. At the shipped receiver size the largest absolute scalar-gain difference between initial and adaptive surfaces across all four rules was 0.001172, at waning fraction 0.04. F-SURF's 0.5 L* limit applies to composited frames and cannot be adjudicated from this difference. The negative controls remove a gain cap, drop below B0, swap the labelled thin limb, and recreate the rejected B2 rule. B2 reaches physical gain 1 at fraction 0.08 in both senses.

### Two protocol details for review

1. The specified reference switches to `unboosted-v5-01` with `lift: 0`. The normal calendar profile has lift 0.003. Both the host's initial-presentation guard and `createInitialMoon` refuse the reference profile. The runtime explicitly identifies it as worker-only. Thus the specified reference measures a separately rendered, unboosted surface at the same altitude. An initial calendar frame can be compared to that identified worker reference after it settles. A tier-matched initial reference would require a different protocol. See `moon/src/moon-native.mjs` 29, 222, 447, 469 and `moon/src/moon-initial.mjs` 37.
2. T preserves scalar gain and, up to Float32 rounding, each receiver's Y. It changes colour even in the near-new cells where the gain cannot increase. In the 540-square initial waxing 0.01 surface, B0 and all three proposals have gain 1. Applying T changes at least one straight sRGB channel at 184,927 receiver locations versus the same rule without T. F-GAIN records this comparison for every rule and phase. These codes precede area filtering and the card composite. The question for G-F2 is how D1's B0-byte requirement is to be applied to a separately waived colour cue. The numerical record chooses no exemption and estimates no native ΔE*ab.

## Horizon and light onset in the native source

The unchanged generated runtime supplies geometry and physical light to a VM test across 17 altitudes, ten fractions (including the exact 0.02 phase boundary) and both senses. All 340 cases compare the geometry weight with the physical light weight, verify eligibility at night, and check that a Sun at −3° or an unavailable surface withholds moonlight. At −1.95° the native light is already eligible for a 0.314 waxing Moon. Moving only the display ramp from `(alt+2)/6` to `(alt+1)/6` sets its weight to zero there, and the test rejects the mutant. Native minute-by-minute composited L* and motion remain to be measured under F-DB and F-TR.

## Native P1 preparation

`tools/qa/r003f_owner_baseline.cjs` implements the **refined B0 owner-scene cell**. At 2026-11-15T09:42Z the current source's ephemeris yields fraction 0.31385485 waxing, altitude −81.90129° and hour angle +174.86967° in Orlando. The offset page overrides only the fraction and sense, preserving time, location and real altitude. The other page takes two B0 captures without Moon overrides, then changes to the specified reference. Each capture waits for empirical adaptive refinement and a composed, Moon-ready card, followed by 2.5 seconds. All four captures check the clock, admitted weather, loaded prayers, native altitude of −81.9° at the diagnostic's 0.1° precision, and ineligible light. Each checks the native and accepted fractions and waxing sense, its expected profile, the refined-calendar display mode, calendar visibility, and full group and feature opacity for the pinned night scene.

The decoder supplies `r003f_p1.cjs` with device-pixel RGBA, the card-relative occluder rectangle, grown header exclusions and an `elementsFromPoint` hit-test mask. The module computes the new-Moon G0 offset, reference P95, fixed lit/dark masks with their overlap count, sRGB-decoded Y and the clipped sky annulus. It reports overall, left, lower and octant sky values. If too few sky samples survive at 1.30R, it records which expansion or hit-test fallback was needed. The fallback retains the 8 CSS-pixel card inset and expanded header boxes. Insufficient sky returns a null sky-dependent metric, independently of the reference-to-candidate margin. Fractions ≤0.02 report only disc statistics. The diagnostic disc aperture is r < 0.9R. For the partial owner phase, a nonpositive reference P95 or failure to produce distinct, nonempty lit and dark masks makes the cell inconclusive (INCOMPLETE). Both B0 readings retain the raw metrics, including any finite margins and the mask overlap count. This check sets no minimum legibility margin.

The native recipe uses the shared R0033 refusing proxy, catch-all context route before the first page, blocked service workers and a WebSocket route. Non-loopback prayer URLs are fulfilled from the re-dated fixture. An in-page shim supplies clear current weather. Every other foreign request is refused. Two transport tests run the actual recipe with a fake browser. A deliberately continued foreign URL raises the isolation exit status even when the measurement itself is incomplete. Synthetic pixel tests cover the card dimensions at DPR 1 and 2, a displaced lit mask, both sky fallbacks, and uniform references equal to, above and below the offset. Scene controls reject a −20° altitude, a swapped phase sense on the reference, and a hidden or transparent Moon. A light-state control distinguishes a missing reading from an actual nonzero light term, which stops the recipe with an Andon.

## Reproduction

Run from the repository root. The headless recipes need Node with WebAssembly and the admitted Moon assets. The native recipe additionally needs Playwright, pngjs, and an installed browser. Use fresh output directories. The native recipe creates its capture directory with mode 0700 on POSIX systems and refuses an existing path.

```sh
node --test tests/r003f-horizon.test.cjs tests/r003f-network.test.cjs tests/r003f-p1.test.cjs
node tools/qa/r003f_gain.cjs --out /tmp/r003f-finite.json
node tools/qa/r003f_gain.cjs --adaptive --out /tmp/r003f-adaptive.json
node tools/qa/r003f_gain.cjs --initial --out /tmp/r003f-initial.json
python tools/cp9/run_native_regressions.py --output /tmp/r003f-population --select native-runner-contract r003f-surface-gains
mkdir /tmp/r003f-runtime
git archive df644ef60156b67b5c487395176369bcec7a0d7b index.html config.js moon real-sky tests/r0002-ordinary.json | tar -x -C /tmp/r003f-runtime
node tools/qa/r003f_owner_baseline.cjs --root /tmp/r003f-runtime --out /tmp/r003f-owner-chromium-1 --engine chromium --dpr 1
```

The capture recipe accepts `--engine chromium|firefox|webkit`, `--dpr 1|2`, and explicit `--playwright`, `--pngjs` or `--executable` paths. It writes the four PNGs, their hashes, B0 repeat differences, the metric summary and the per-request ledger. For every changed repeat pixel beyond 1.06R, `outside-repeat.jsonl` lists device coordinates, signed RGBA deltas, distance from the limb in CSS pixels and the hit-test element stack before the reference switch. A hit-test stack locates a pixel for investigation and cannot establish which compositor layer changed it. A measured cell exits 0, incomplete exits 2, isolation failure exits 3, and observed physical light in the calendar-only regime exits 4.

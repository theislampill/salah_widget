## Implemented machine

One invocation of `python tools/build_native.py` on a repository root R.

| Phase | Entered when | Tree effect |
|---|---|---|
| `planning` | script start | none |
| `computed` | every output, including both Moon-expanded entries, is in the in-memory `Outputs` map `G` | none |
| `validated` | every guard below has passed (they run during computation) | none |
| `publishing` | `generated_outputs.publish` has staged all changed bytes and replaces the first file | per-file `os.replace` |
| `published` | changed files replaced, stale owned files removed, `GENERATED.json` written last | complete |
| `failed-before-publish` | any guard or input error, an interruption, or an I/O error while staging | **none** (staging removed in `finally`) |
| `failed-during-publish` | an I/O error after the first in-tree replacement | replaced/removed paths printed to stderr as JSON; rc ≠ 0; recovery is a re-run |

Owners:

- `tools/generated_outputs.py` owns the guard primitives (`GenerationError`, `require`, `replace_exact`), the
  declared generated-path set, the prior inventory G₀, stale-file selection and publication.
- `tools/build_native.py` computes the native outputs and calls `build_moon.plan_moon` with the **staged**
  entries; it calls `publish` once, at the end.
- `tools/build_moon.py` `plan_moon(root, entries)` runs the Moon preflight on the given entry texts and returns
  its outputs (worker, chunks, host, compact files, both expanded entries, `BUILD.json`) without writing.
  `build_moon(root)` is kept as the direct form (reads the entries from disk, plans, publishes without an
  inventory) and still refuses already-expanded entries before any write.

### Guards

- Every former `assert` is an explicit exception, so `python -O` changes nothing:
  `native_star_bootstrap.py` manifest pin (message `manifest drift`), catalogue identity, bootstrap size bound;
  `build_native.py` elevation anchor (now `replace_exact`). An AST check in the census test forbids `assert`
  in the four builder files.
- Every "count" site of the issue's §2 census goes through `replace_exact(text, anchor, replacement, owner,
  count=1)`, which raises naming the owner and the anchor: elevation hook, `beginSkyScene` hooks,
  `commitSkyScene` notify hook, `boot()` hook insertion, `</head>` stylesheet link, config tag + first-paint
  script (its earlier exact-count guard is kept), `</body>` native-sky script, offline inline `config.js`,
  offline inline stylesheet, offline inline data + native-sky scripts, worker template `WORKER_SOURCE` and
  `PHYSICAL_MODE`, `build_moon` `export ` strip of `native-cloud-transfer.mjs` (expected count = the number of
  line-start `export` declarations), `build_moon` offline `</body>` chunk tags.
- Added beyond the census (same class): the starfield block markers `// PROJECTED STARFIELD:` and
  `// Accepted target/explicit anchor` and the `function _mb32` line must each occur exactly once (they were
  located with `index`/`re.search`, which take the first match silently).
- Exempt whole-text sites, each with its reason recorded in the census test: import/export stripping (a leftover
  raises `Unbundled import/export`), path-separator normalisation (two sites), `</script` escaping (two sites),
  and the universal-newline decoding of staged bytes (`text_of`, equal to `read_text`).
- Kept unchanged: the R0027 and horizon digest-guarded transforms, the Moon asset/WASM/receiver/ancestry/source
  association checks and the entry-boundary preflight.

### Ownership, inventory and stale files

- Declared generated set: `generated_outputs.DECLARED_EXACT` (root entries, `config.js`, `builder.html`,
  `GENERATED.json`, the four `real-sky/native-*` generated files, the eight copied notices, `moon/moon-worker.js`,
  `moon/moon-host.js`, `moon/BUILD.json`, `moon/assets/initial-compact.bin`, `moon/initial-compact-manifest.json`)
  plus the generator-exclusive patterns `real-sky/core/{src,integration}/*.mjs` and `moon/file-data/*.js`.
  `Outputs.add` refuses any other path, so the builder cannot write outside the set.
- G₀ = the paths named by the previous `GENERATED.json`, filtered to the declared set (else, on the first run,
  the built-in exact list), plus the files currently present under the two exclusive directories that match
  their patterns. Removed = G₀ \ G. **Operator note:** the sweep removes any `.js` file in `moon/file-data/`
  and any `.mjs` file in `real-sky/core/src/` or `real-sky/core/integration/` that the current build does not
  produce, **tracked or untracked** (a hand-placed copy included). Keep nothing of your own there. A forged or stale inventory cannot widen deletion (its undeclared entries are
  reported as `ignoredInventoryPaths`); an unreadable inventory fails before publish.
- `GENERATED.json` (new, root, published on Pages): schema `salah-generated-inventory/1`, every generated path
  except itself with `bytes` and `sha256`, deterministic (sorted, LF). `moon/BUILD.json` keeps its schema and
  bytes.
- The final JSON report keeps its previous keys and adds `phase`, `written`, `unchanged`, `removed`,
  `crossVolumeCopies`, `inventorySha256` (and `removedPaths` / `ignoredInventoryPaths` when non-empty).
- Unchanged files are not rewritten. Staging is a `tempfile.mkdtemp` directory (honours `TMP`); if `os.replace`
  reports a cross-volume move, the file is copied beside its target and replaced from there.

### Invariants

I1 no detected failure leaves an in-tree change · I2 `-O` does not change validation · I3 a drifted anchor fails
the build · I4 stale owned outputs never survive a successful build · I5 identical inputs give the committed bytes.
Not claimed: a multi-file publish is not atomic as a whole (per-file replacement); an I/O error mid-publish is
reported, not rolled back.

## Decision gates

- **DG-1 concurrent builds: default (a) taken — document "one build per tree", no lock file.** Conservative: no
  new artefact, no product, privacy or external effect. Stated in AGENTS.md (CP9 source ownership), in the
  builder docstrings and here. Two concurrent builds on one tree are unsupported; nothing detects them.
- Executor choices the issue leaves open: inventory name `GENERATED.json` at the root (it inventories root
  entries as well as Moon files); helper name `replace_exact`; staging in the OS temp directory.

  builder inputs and committed outputs (no git, no network), with `TMP` pointed at a per-run directory whose
  emptiness afterwards proves staging cleanup.
- `tests/real-sky/native_spectral_cache_build_test.py` (R0027): `check_builder_invokes` is **re-expressed**. The
  builder no longer leaves a partial tree, so a wrapper runs the real builder script unchanged and records each
  staged output (`Outputs.add`) into a directory outside the tree. The check compares those staged core files
  with `bound_spectral_cache(vendor)` and `correct_horizon(vendor)` as before, and also requires that the failed
  build created nothing in the tree. Its bypass mutant now removes the corresponding new builder line
  (`elif p=='src/spectral.mjs':data=bound_spectral_cache(data)`) and is still killed. `check_builder_fails_closed`
  is strengthened to "no in-tree file written at all".

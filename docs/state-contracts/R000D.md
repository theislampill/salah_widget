## Defect (base)

Retry **spacing** is measured on the wall clock while the attempt **deadlines** already use the elapsed clock:

- `fetchWeather` L1375-1377: `const now=Date.now(); … if(now-lastWxTry < 60*1000) return;`, stamp `lastWxTry=now` L1382.
- `fetchRadar` L1451: `const now=Date.now(); if(now-lastRadarAt < _RADAR_REFRESH) return;`, stamp `lastRadarAt=now` L1455.
- Deadlines: `beginAttempt` L1039 / `attemptEligible` L1043 use `_RAFNOW()` (L873; `performance.now()`, else `Date.now()`).

After a backward wall correction of S, the accepted record is correctly future-dated and ineligible
(`weatherEligibility` L1295-1304, `radarEvidence` L1411-1417), but the wall delta keeps the replacement blocked
for S + 60 s (weather) / S + 600 s (radar). A forward step opens the spacing early.

## Owner decisions (2026-11-11, binding defaults)

- **D1** native qualification on the existing controlled Windows route, targeted Chromium **and** Firefox, with
  independent controllable wall and elapsed clocks inside the fixture (never the OS clock); full sequence
  accepted → backward wall correction → future-dated rejection → elapsed eligibility → actual replacement →
  owned completion → visible consumer recovery; 60 s / 600 s boundaries and stage deadlines preserved.
- **D2** without `performance.now()` use the existing `Date.now()` fallback; expose/document the degraded
  wall-clock guarantee; no clock-discontinuity guard; no sleep/background-resume claims.
- **D3** small explicit per-source elapsed retry record with an unset sentinel distinct from elapsed zero;
  distinct weather/radar domains; UTC evidence ages, ownership, deadlines, poll opportunities and freshness
  rejection unchanged; no scheduler, interval loop or clock manager.

  on resume, not the real gate).

  OS sleep / background-resume behaviour is UNKNOWN and not claimed.

- Radar has no visible or accessible consumer in this build (see ES0D-14 above); its recovery is observable only as
  admitted state in `qaState()`.
- Preview mode (`_clockPreview`/SIM) keeps its existing record-retention selector; the shortcut's negative-delta
  rejection relies on live `selectedWeather()` eligibility (mutation "accept negative receipt shortcut").
- ES0D-13 follows the current config contract (any non-appearance change clears both records); per-source reset
  belongs to R0003.

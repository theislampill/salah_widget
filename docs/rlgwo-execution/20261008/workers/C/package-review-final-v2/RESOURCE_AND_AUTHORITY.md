# Execution resources and authority boundaries

This planning package does not authorize new production implementation, merge or issue closure. The current owner authorized source/specification reading, documentation-only publication, expanded issue comments, priority reasoning and DAG construction. The separate startup thread retains its already-authorized implementation, qualification and Draft PR scope.

The proposed third-thread launch prompt will distinguish authorization on invocation for bounded implementation/evidence branches, reviewable commits/Draft PRs, issue certificates and justified closure from separately approved merges/deployments. An issue whose remaining obligation requires delivered changes cannot close from an unmerged branch. Evidence-only completion must bind an actually delivered unchanged consumer; it requires no fictional runtime rewrite.

Resources for the later executor:

| Resource | Capacity | Ownership / rule |
|---|---:|---|
| Independent reasoning/spec/source review | Up to6 Sol6.1/max workers | Verify requested and recorded configuration; disjoint writers, no recursive delegation |
| Heavy browser/terrain/performance machine | 1 | Currently held by startup thread; explicit release/lease; all costly C/F campaigns serial |
| Shared authored/generated integration | 1 | Primary integrator owns final join, source hashes, builders and commit order |
| README/DESIGN/ARCHITECTURE text integration | 1 writer | Parallel issue-specific drafts permitted; named sections merged by one documentation integrator |
| Native Apple Bash3.2/macOS host | Unavailable/unverified at planning intake | Acquire exact required platform early; Linux, PLATFORM=mac mock or disabled builtins do not qualify it |
| Windows PowerShell5.1/7 | Existing valid native receipts | Reuse only exact-source/fixture equality; acquire actual host when affected |
| GitHub issue writes | Per-issue designated writer, primary-approved body | Fresh contract/source/state -> marker lookup -> comment -> readback -> authorized eligible close -> final readback |
| Main merge/Pages deployment | No permission inherited from PR42 | Explicit owner approval for exact reviewed next heads and proposed release gates |

Hard dependency means a named input/interface/output is required. Resource contention is represented in resource reservations, not artificial hard edges. Administrative issue closure is not an interface prerequisite. A ready P2 can run while a P1 waits for a native host; priority does not change.

Source changes are authored in src/native/, real-sky/native-* and moon/src/ or declared builder adapters. Root index/offline/bundles/copied core are generated. Frozen v1/, vendor/reference materials, PR38 and unrelated worktrees are excluded. No reset/clean/stash/rebase/force push, user-profile clearing, real clipboard use or system-clock alteration. Restart recovery checks existing effects/processes/ledger before retries.

Evidence invalidation is by changed semantic owner, inputs, platform and consumer boundary. Pure helper receipts can retain applicability when their actual source and interfaces are proven identical. Native joined scene, timing, lifecycle and composition receipts need affected reruns when source changes can alter those behaviours; a whole-runtime hash alone is neither automatic rejection of all retained evidence nor automatic proof of equivalence.

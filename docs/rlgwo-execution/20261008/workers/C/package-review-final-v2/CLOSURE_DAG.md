## Edge semantics and integration boundaries

- `hard-interface`: a named produced artifact/interface is genuinely needed to execute the consumer. Each edge names its reason; where it consumes an output, that output ID must exist at the producer.
- `qualification`, `review`, `integration`, `closure`: the earlier proof/review/delivery result is required before declaring the later stage complete. This is distinct from the ability to draft its fixtures/docs earlier.
- `authority`: a concrete owner decision is required for an external effect or a genuinely unresolved contract choice. Completed PR42 merge authority is not a new merge permission.
- Shared files, platforms and browser machines are **resources**, not automatic hard edges. A single integrator serializes final shared-source/generated writes. Parallel independent drafts and case data are safe when their writers are disjoint.

The important potential cycle is split deliberately. Startup investigation supplies its actual candidate identity/contract to the settled lunar-display increment. L1 does not depend on administrative #33 closure, and #33 does not require #34's unrelated original cost/eligibility work merely to receive that one result. Original callback-cost obligations remain separately mapped. A source-handoff receipt is not startup acceptance.

Default UI contrast and weather-information work may be designed against the current delivered interfaces without waiting for the entire lunar programme. If their required review/qualification completes earlier, they may form independent proposed PRs. A later display/markup change must rerun the specifically affected contrast/header/row/accessibility cases; it cannot reuse an earlier closed issue as a blanket regression waiver. Do not create a false all-backlog join solely to reduce the number of PRs.

Documentation-only release is deliberately earlier than complete issue closure. Its `RELEASE-REVIEW` consumes only the exact DOC/DOCS facts and candidate, followed by its own exact-head authority and documentation delivery. Where an authored node combined distribution with all native proof, `DELIVERY-CONFIRM` retains those original output IDs and full proof requirements. `CLOSE` still waits for every original native/evidence obligation plus actual docs delivery. This corrects the false #19/#16 ordering without treating missing native proof as passed. One actual approval/delivery receipt may satisfy several per-issue nodes when—and only when—the approved head, base and effects scope are the same; no duplicate owner request or merge is needed.

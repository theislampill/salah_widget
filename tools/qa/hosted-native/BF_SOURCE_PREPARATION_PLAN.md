3. Root publishes the exact reviewed collector tree to an inactive source branch

5. Root checks actual source currentness, remaining capacity and workflow identity,

## The dedicated job

The exact workflow checks out the collector, target, research, baseline and
historical sources at their declared immutable identities. It installs the fixed
source SDK, calls the original common and R002F builders under their existing
bounds, then runs the fixed narrow source admission and the two distinct negative
native-facing admissions. The exact command construction is centralized in
`command_for_phase`; the child source check is `check_source` and the specific
common refusal is `refuse_native_common`. The latter does not catch or relabel
the original native-isolation error.

`bfcache_source_preparation.py run --task <actual-fixed-task> --workspace <actual-fixed-workspace>`
uses actual provider environment identities and refuses different branches,
targets or runtime versions. `seal` has the same fixed task/workspace contract.
Source and runtime paths are literal, complete, private and freshly owned where
the route creates them. No prior prepared task is reused.

On incomplete work, retain actual original process/stream prefixes, failures and
available populations. A missing child terminal record remains missing. R002F's
original wrapper produces an aggregate and nine raw stream pairs; it does not
produce individual structured child records, and this collector invents none.
Only bounded encrypted shard/index pairs may be uploaded. A failed sealer is not
represented as a successful evidence export.

## After the actual job

Root authenticates the actual run, attempt, job, source head/tree, artifact and
terminal step outcomes. The pretrigger configuration template becomes a concrete
observed binding only at this point. Provider/API limitations or transport
failures retain their actual outcomes; no fictional resource record is supplied.

Root downloads the same exact encrypted artifact with measured capacity and
streaming closed ZIP/ciphertext checks. The source-only raw-shard opener uses
fresh private shard directories, validates the encrypted index and exact ordered
object population, and preserves opening/process/raw custody. No private key
leaves the root operator, and no raw plaintext is publicly uploaded.

The fixed offline operation is:

```text
<pinned-python> -B <reviewed-reader>/bfcache_source_preparation.py inspect
  --index <actual-restored-index-directory>
  --objects <actual-closed-raw-object-directory>
  --binding <actual-root-authenticated-binding-json>
```

It requires only relocated raw objects and metadata. It does not reconstruct a
second multi-gigabyte live prepared task or rerun original builders/admissions on
the receiving host. A separate root anchor joins the same artifact/index/object
population to trusted immutable local trees and actual public mappings. Retain
both independent receipts and their exact source, argv, interpreter and raw
streams; require both before any combined source-preparation verdict.

Independent retained-evidence review follows actual opening, process inspection
and anchor. A successful source-only verdict does not authorize or manufacture
BF tools, Ubuntu24.04 runtime, actual acquisition, system provisioning, privileged
namespace controls, browser execution or scientific observation. Those original
native gates are still separate. No candidate threshold, wait, sample count,
owner ephemeris, progression rule or acceptance policy is changed here.

## Fixed source and runtime contract

`bfcache-source-preparation.json` declares the entire 16-file collector population,
the complete original target manifest (111 files), and the three original source
roles. The provisional design count of 15 gained the repository-required
descriptive `IMPLICIT_STATES.md` note. The actual populations are 16 collector,
111 target, 1,012 research, 931 baseline and six historical files: 2,076 logical
source files. These counts do not replace full path/body/mode/immutable-tree checks.

The workflow materializes five separate exact source checkouts. The collector
compares every declared body and executable mode with its actual Git blob, checks
clean HEAD/tree identities, and verifies the complete raw target manifest and
selected campaign pins. For the target it also joins an independently read

map. Those original rows include literal and resolved paths, size, hash, mode,
UID, device, inode, link count, timestamps and symlink facts. They are preserved
whole, then checked before and after the actual source operations. Compact Git
rows and physical records are different schemas; direct dictionary equality
between those schemas is not an admission.

The source host is Ubuntu 22.04 with Node 24.14.0 and Python 3.11. Exact locked
Node and Python SDK dependencies are installed with package scripts and managed
browser downloads disabled. Their real package versions, file inventories,
interpreter identities, processes and raw streams are retained. The five-key SDK

`task/runtime.json`. The managed-browser directory, original acquired runtime,
native isolation records and BF tool-acquisition directory must remain absent.

## Encrypted raw-object custody

Logical source, generated, receipt and stream files are deduplicated by full raw
SHA-256 and size. Each data shard contains at most 94 MiB of raw objects and is
sealed with the unchanged original capture transport, envelope and saved-recipient
public certificate. Its ciphertext is bounded by 96 MiB. A separate encrypted
index binds every logical file, raw object, ordered shard, source identity, run,
attempt, receiving target and workflow identity. At most 16 data shards, 12,000
logical files, 3 GiB logical bytes and 768 MiB unique bytes are accepted. The index
has a 16 MiB plaintext bound and an 18 MiB ciphertext bound. There is no compression
codec or plaintext artifact upload.

The sealer measures actual free space and the actual complete unique population.
Its reserve is `2*unique + 4*96 MiB + 4*18 MiB + 256 MiB`. The earlier 589,794,754-byte,
eight-shard estimate came from old1107 metadata plus the fixed source extension;
it is sizing evidence only. An actual job must satisfy the measured bounds with
its own bytes and preserve a refusal if it cannot.

The workflow's `records/coordinator.stdout` and `records/coordinator.stderr` are
part of the closed retained record set. There is no invented structured outer
workflow-process receipt. Provider step outcomes remain separate. The sealer's
own still-open top-level terminal streams are outside the sealed snapshot; a
failed sealer produces no successful payload, and plaintext remains ineligible
for artifact upload. Its actual provider failure is preserved as that boundary.

Only the root receiving operator authenticates/downloads/opens the actual artifact.
Every shard gets a fresh owned temporary directory. Missing, duplicated, reordered,
substituted or extra shards/objects are refused. Download receipts use literal
`shards/0000`-style ordered paths; the index and opener use bare `0000` IDs. Their
strict bridge is the literal `shards/` prefix, not permissive normalization.

## Offline reading and the independent anchor

The fixed `inspect` operation checks the complete raw-object population, each
retained source Git body, all original source/generated/patch/runtime metadata,
recorded SDK currentness, exact command/stream/PID ownership, complete physical
source currentness, fixed plan and specific refusals. It executes no retained
code and builds or rematerializes no prepared task. Hosted path strings are
interpreted only as recorded logical identities; receiving inode identities are
not substituted for them. Both raw-object and source-map readbacks remain bound
to the same encrypted index and externally supplied exact binding.

Its successful status is only
`SOURCE_PROCESS_GATE_PASS_PENDING_IMMUTABLE_ANCHOR`. An independently reviewed
root anchor must separately derive all five role populations and path/mode/blob/
size/hash identities from trusted local immutable Git trees, joined to the actual
authenticated public commit/tree mappings. The raw target-manifest pin is mandatory.
Self-consistent retained source rows do not establish membership in those trees.
Only the process gate and anchor on the same authenticated open population can
support a genuine source-preparation verdict. Neither supports native admission.

Actual incomplete results and source drift remain `INCOMPLETE`, including genuine
SIGKILL, timeout, retention and missing-process outcomes. This collector does not
turn earlier failed local preparations into passes or transplant their receipts.

## Reconstruction and controls

The first mutable BF collector author tree and its unarchived controls were lost
in a workspace replacement. This implementation is a new reconstruction from
the preserved exact design/addendum, actual old97 source, fixed target585c source
and original dependencies. Reproducing an old payload or workflow digest does not
recover the missing old process evidence. Every new attempt has its own retained
source map, argv, raw output, actual exit and currentness readback.

The registered controls cover the bounded payload, exact fixed routes, full
physical/Git join, source SDK shape and absence, original refusal meanings,
original blocked plan, child ownership/raw streams, timeout/exception teardown,
closed CLI and failure precedence. Separate author metadata controls use retained
old1107 metadata with explicit provenance. They do not execute builders, restore
bulk objects or qualify the fixed new target. Earlier failed controls and partial
attempts remain preserved alongside successors.

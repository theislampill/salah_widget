## Failure retention and ordering

For still, hidden and ordinary ineligible captures, raw screenshot bytes and
both scene observations are recorded before original physical or new UI
rejection. A failed after-state read is represented as `after: null` plus the
actual error. The before-state is never substituted for it. Retention faults
are recorded separately; an original physical Andon remains the controlling
failure even when a write or after-state read also fails.

The original ineligible gate runs before its screenshot. If it fails, the
harness may obtain one distinctly named, supplemental post-failure observation
with a bounded screenshot request. That record retains the original error and
cannot supply an original capture, metric or admitted frame. Missing data remain
missing; no placeholder PNG, clock record or successful state is fabricated.

UI admission is deferred until the original group procedure and original
fixture-consumption checks finish. This preserves a later physical Andon that
an earlier UI failure must not hide. All successfully acquired raw artifacts
remain in the original artifact inventory.

Motion streams are registered when attempted. Their exact acquired frames,
setup/transport/retention errors and partial cadence remain available on
interruption. Each frame retains the original acquisition `started`/`ended`
boundaries; added host disk writes occur after `ended`. UI observation itself
adds work inside the facts read, so these instrumented observations cannot be
represented as unchanged original performance timing. Empty or partial streams
never acquire a clip or a completion claim by substitution.

Page crashes, unexpected page closure/browser disconnection and cleanup errors
are recorded. Every available cleanup is attempted. Final original isolation
failure retains exit 3 and dominates all other dispositions. Original physical
Andon retains exit 4 and dominates UI, retention and cleanup errors. Other
incomplete acquisition or lifecycle cases retain exit 2. A summary write failure
cannot produce a successful exit; its missing summary remains missing for outer
process admission. Hard process termination can leave only the raw files already
written; the outer timeout/process receipt must retain that fact.

identities and FFV1 frame/clip pixel equality. Original acquisition status alone

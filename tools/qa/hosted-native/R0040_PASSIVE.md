# R0040 passive capture diagnostic

This is a separately identified diagnostic source packet for independent review. It
adds observations to the reviewed Date-only capture route. It does not repair,
replace or reinterpret any earlier native acquisition or verifier result.

## Approved scope

The original capture driver, historical helper, Date-only entry, capture
retention entry, generated product, Moon worker and lossless verifier retain
their exact bytes. The eight original capture arguments remain unchanged. The
diagnostic does not change product predicates, source selection, renderer math,
timers, animation scheduling, the original sample array, PNG production or CDP
screencast acknowledgements.

The new leaf entry requires the original complete source/preparation and
current namespace admission before importing an original helper or browser. It
executes the unchanged driver through the reviewed Date-only adapter. The
existing final admission stays intact; a distinct supplemental receipt binds
the passive observer and sampler identities. A future coordinator selection
must require both receipts and the actual terminal process status. This source
packet alone activates no campaign.

## Observations

- A bounded main-world observer records Worker construction, selected primitive
  boot/message/error fields and termination calls. It forwards the same native
  constructor, method arguments, return values and exceptions. It never copies
  worker source, image buffers or message payload arrays.
- Existing Playwright worker creation/close and response metadata events are
  recorded in a separate bounded host buffer. Response metadata uses already
  received status and provisional headers, without fetching response bodies or
  requesting another header round trip. Browser response rows use the existing
  capture request IDs. Local server finish/close/error records have their own
  IDs; matching URLs do not establish a unique cross-layer association. Node
  error observations use `errorMonitor`, so an unhandled request, response or
  server error still throws its original exception. Existing error handlers
  retain their original delivery.
- At the existing readiness return and before original context cleanup, an
  explicit read calls only `SalahMoonRuntime.observe()` and the pure `disposed`
  getter. Fixed primitive fields are retained. The adopting `state` getter,
  `surface`, `detailEnabled`, retry, refresh and disposal are never called by the
  observer. A missing runtime or an observed worker failure is evidence, not an
  added product acceptance predicate.
- The exact pinned isolated-world sampler expression receives a reversible
  diagnostic extension. A separate bounded numeric buffer stores the original
  sample ordinal, rAF timestamp, callback-entry time and time immediately after
  synchronous dispatch. The original dispatch, sample push and rAF requests
  execute in their original order. The raw original response is returned
  unchanged. Supplemental extraction occurs after the original stop expression,
  or as a clearly incomplete prefix before cleanup following an earlier failure.

Main-world, isolated-world and host clocks remain separate. Only values from
the same clock domain may be subtracted. Host event arrival is not worker
execution time, a returned sampler callback is not physical display, and a
nearest timestamp does not prove unique frame association.

## Failure and retention contract

The added buffers contain bounded primitive records. Overflow, failed
evaluation, absent sampler extraction and contradictory instrumentation metadata
remain explicit. Raw prefixes are retained before validation. The original
report and partial PNGs are never rewritten. Original exceptions and nonzero
exits retain precedence; a prevented external continuation retains exit 86.
Supplemental retention failure must be visible in the actual terminal exit and
cannot publish a successful passive receipt.

The supplemental final file is `passive-observation.json`, with protocol
`r0040-passive-final-observation/1`. Its success label is
`ADMITTED_PASSIVE_DATE_ONLY_FOR_OFFLINE_VERIFICATION`. The existing
`final-admission.json` retains the reviewed Date-only protocol and contents;
the supplemental receipt binds its bytes and its clock proof. Either file
alone is insufficient. `admitPassiveReceipt` requires the actual child exit,
recomputes every supplemental inspection from the retained raw prefix, checks
the complete sampler population against the original untrimmed samples, and
requires both source identities. A supplemental terminal journal event records
the expected status; the external process result remains authoritative if final
retention itself fails.

No new per-frame host copy, hash, fsync, CDP listener or acknowledgement is added.
Additional clock reads and bounded in-memory bookkeeping still have overhead.
Startup/readiness/cleanup evaluation and final serialization are also declared
instrumentation. These observations are not original performance measurements
and do not confer cadence, physics, visual or owner acceptance.

## Approach and controls

The approved approach is a leaf subclass/adapter around unchanged reviewed
functions, plus an exact-expression sampler extension. A product or worker
patch would change the object being investigated. Per-frame host tracing would
add acquisition work to the original PNG/acknowledgement path. Both are outside
this bounded design.

Source controls execute the pinned original driver and helper with bounded
browser/CDP dependencies, and execute both original and instrumented sampler
expressions in deterministic JavaScript contexts. They check identical
original sample contents, scheduling and response identity; unchanged worker
constructor/method behavior; refusal of byte drift; bounded raw-prefix retention;
and original error, timeout, cleanup, retention and veto precedence. These are
offline instrument controls, not native capture observations.

The registered command `hosted-native-r0040-passive-controls` declares 24 cases
and the complete new leaf, original capture/helper, reviewed retention, Date-only
control support and preparation-manifest input closure. The HTTP control uses
the exact immutable historical helper and a synthetic loopback asset. It checks
asset/404 response parity and final server response events without a browser.

```sh
python tools/cp9/run_native_regressions.py --output NEW_PRIVATE_CONTROL_DIR \
  --select native-runner-contract hosted-native-r0040-capture-retention-controls \
  hosted-native-r0040-dateonly-controls hosted-native-r0040-passive-controls
```

## Handoff boundary

This packet changes no coordinator, planner, workflow, campaign, product,
preparation recipe or original Date-only entry. Independent source review must
qualify this exact leaf tree before central integration. A later opt-in route
must pin the final leaf/dependency hashes, re-admit the acquired runtime and full
current source closure, require genuine original preparation/entry success and
the current namespace, and bind the unchanged eight capture arguments. It must
inspect both final receipts with the actual child result while retaining outer
timeout/isolation precedence and the existing exit-86 stop behavior. It cannot
translate the supplemental acquisition label into a generic product PASS.

The added evaluations are bounded individually at five seconds. A future route
budget must include those startup, readiness, post-stream and cleanup operations;
the existing capture ceiling is not silently widened here. The unchanged
lossless verifier and human review remain separate after acquisition. Existing
native failures and owner decisions retain their original disposition.

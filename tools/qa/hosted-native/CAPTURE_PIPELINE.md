## Producer completion and limits

The workflow runs acquisition and observation through `capture_pipeline.py run`.
The caller launches the same original command, with the same source arguments,
and waits for its actual exit. Original stdout/stderr stay under the private
capture root. Exclusive started/completed receipts bind the actual argv, current
caller/producer/campaign source hashes, phase, return code, interruption state and
elapsed interval. A copied result label is insufficient.

Before sealing, the caller requires ordinary completion of acquisition and, when
acquisition succeeded, observation. It requires the original terminal aggregate,
complete ordered planned lane population, and actual namespace process records
for every launched lane. A documented NOT_RUN lane has no namespace process.
The aggregate engine/work-order population must match the current campaign;
every lane retains its planned identity, known original status and complete
namespace row, and the aggregate status retains the original priority. Unknown
or partial terminal records refuse transport rather than supplying an oracle.
Completed namespace failures and controlled namespace timeouts remain failures
and can be retained. A failed ordinary acquisition can retain acquisition-only
evidence if no observation was started. A completed failed preparation has no
invented lane population.

The producer-stop argument is deliberately source-bounded: acquisition is
sequential foreground work; completed observation synchronously waits the known
namespace commands, and their PID-namespace init termination removes descendants.
The observer launches namespace commands in separate sessions, so an empty outer
process group would not prove their termination. This caller makes no such claim.
Forced, signaled, interrupted, missing, exceptional or ambiguous outer completion
refuses sealing as PRODUCER_INCOMPLETE. The interrupted wrapper requests original
observer cleanup, then bounds its own wait; this does not prove all escaped
descendants stopped. Safely retaining evidence from an abruptly lost outer
coordinator would require separately reviewed broader descendant supervision.
This integration does not establish that stronger behavior.

The private task parent and immutable checkout are trusted custody, as in the
unchanged envelope. No claim of an atomic snapshot against another writer with
the same account privileges is made. The source-bounded completion gate is not a
product PASS, proof that a recipe passed, or authentication of a sender.

## Staging, encryption and cleanup

The caller binds protection to the actual orchestration/research/baseline/
historical roots and fixed acquired build/runtime/browser/cache/config locations.
Capture data cannot name a replacement protection root. A fresh mode0700
capture root and its ancestry must pass symlink checks before any producer
receipt or stream is created. Source paths containing `..` are refused; the
same admitted canonical paths are used for protection and actual producer argv.
A fresh mode0700
`transport-work` reservation holds the private mapping and numeric payloads.
The entire stage is encrypted by unchanged `envelope.py`; the strict path,
case-fold, complete-population and CMS rules remain byte-identical.

The public upload population remains exactly `capture.p7m` and `envelope.json`.
Logical names, mapping and payload bytes remain inside the ciphertext. The
caller removes only a staging reservation whose inode ownership was acquired.
An exceptional identity-read failure immediately after directory creation
refuses with CLEANUP before payload or cryptographic work. Its empty private
reservation may remain: without an ownership token the caller must not delete
a possibly substituted directory by name. Once ownership is established,
success/error cleanup uses that token. Offline parent-descriptor acquisition
occurs before any temporary reservation, closing the earlier setup leak. The
workflow's final cleanup removes the entire fresh per-run task, covering staging,
tentative envelope files, logs, disposable builds, runtimes and downloaded caches.
It occurs after attempted ciphertext upload.

The seal step now has a20-minute ceiling for bounded staging, verification and
unchanged cryptographic I/O, replacing the old8-minute seal ceiling. The original
observation budgets and original waits are unchanged. The4GiB transport limit is
a population ceiling, not a promise that every near-limit population will finish
within the deadline. Deadline exhaustion remains failure; no truncation occurs.
The new I/O overhead is uncalibrated until native evidence is obtained.

Public errors are fixed categories only. They distinguish incomplete producer
custody, stage rejection, envelope rejection, restoration and cleanup without
printing private paths, exception text, data, command logs or key material.
These categories describe the current attempt; they do not explain erased past
errors. Upload is conditional on full caller success, including stage cleanup.

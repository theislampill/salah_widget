# R002F-A2 hosted native probe

An optional [headed tab-hide diagnostic](R002F_TABHIDE.md) is reconstructed in a
separate source-bound entry. `r002fRoute=tabhide` selects that distinct lane; the
default offscreen prayer/preview entry documented below is unchanged. The new
entry has its own source review, preparation and observation requirements.

This instrument reconstructs the lost native probe for the **existing, unadopted**
combined R002F-A2 research candidate. It does not change product owners, generated
entries, policy, the failure ledger, or research disposition. Its two separate
observations are prayer DOM publication on real offscreen restoration, and native
canvas selection during a preview upload fault and lunar-authority withdrawal.

The controlling source contracts are
[`R002F-A2-lifecycle-investigation.md`](../../../docs/state-contracts/R002F-A2-lifecycle-investigation.md),
[`R002F-A2-preview-transaction.md`](../../../docs/state-contracts/R002F-A2-preview-transaction.md),
and the existing guarded
[`materialize.cjs`](../r002f-transaction/materialize.cjs). The original issue 96
and its comments remain the policy record. No result here closes that issue.

## Build custody

`r002f_prepare.py` accepts a genuine main checkout/archive and the immutable
combined research checkout. It verifies the known main entry and inventory,
compares product/build inputs between them, checks the existing materializer's
source identities, and copies inputs into fresh disposable directories. It
applies the materializer's exact combined patch only there. It runs the canonical
native builder twice in each arm, checks every generated file, and runs frozen V1
preservation, its disposable tamper control, and the Pages inclusion preflight.
The inputs are checked again after building.

Run from the orchestration checkout, using absolute caller-supplied paths:

```bash
python tools/qa/hosted-native/r002f_prepare.py \
  --research "$R002F_RESEARCH" --baseline "$R002F_MAIN" --out "$R002F_BUILD"
```

`R002F_BUILD` must not already exist and must be outside both inputs. Its
`baseline/` and `candidate/` are the actual served trees. `build-result.json`
contains relative file identities, the materializer manifest and both build
receipts. Detailed command output stays beside that receipt. A successful build
prints `R002F_BUILD PASS` and exits 0; failure prints `INCOMPLETE` and exits 2.
Each subprocess is bounded to 180 seconds.
The wrapper opens exclusive mode-0600 stdout/stderr files before launching each
child, so output already emitted by a timed-out child remains available. The
timeout still kills and waits for that child. Successful stdout is read back for
the canonical builder's JSON checks. The reviewed wrapper SHA-256 is
`447e419d34c49512429c7860f5cf8608446f51946e1a44dfe3e5650047d4a48b`;
receipts from an older wrapper require a fresh preparation for hosted admission.

## Native launch and isolation

All browsers must run under the coordinator's already verified nonroot network
namespace. Before loading Playwright or launching any browser, the probe requires
`SALAH_HOSTED_NATIVE_ISOLATION_RECEIPT` to name a private JSON receipt with:

```json
{
  "protocol": "salah-hosted-native-isolation/1",
  "passed": true,
  "uid": 1234,
  "netns": "net:[CURRENT_NAMESPACE]",
  "outerNetns": "net:[DIFFERENT_NAMESPACE]",
  "browserControl": {"passed": true}
}
```

These example values are not an isolation receipt. The probe compares the real
process UID and `/proc/self/ns/net` with the receipt, requires a nonzero UID and a
different outer namespace, and requires successful browser controls. The
coordinator must have actually run the kernel and browser isolation controls.
The probe consumes that evidence; it does not manufacture it.

```bash
node tools/qa/hosted-native/r002f_probe.cjs \
  --playwright "$PLAYWRIGHT_DIR" \
  --baseline "$R002F_BUILD/baseline" \
  --candidate "$R002F_BUILD/candidate" \
  --out "$R002F_RESULT" --engine chromium --dpr 1 --rounds 1
```

`PLAYWRIGHT_DIR` is the explicit installed Playwright package directory, not a
download request. The probe records the package version, hashes the executable
returned by that engine, and explicitly launches that exact executable. Chromium
uses `chromiumSandbox: true`. Each context blocks service workers. The local
servers bind only to loopback. Known prayer, weather and empty-radar requests
receive disclosed fixtures; unexpected external requests and WebSockets are
aborted and invalidate admission. This routing is additional to process-level
isolation, not its replacement.

`--engine` accepts `chromium`, `firefox` or `webkit`; `--dpr` accepts 1, 2 or 3.
`--rounds` defaults to 5 and accepts 1–10. `--section all|prayer|preview` defaults
to `all`. `--timeout-ms` defaults to 120000 and accepts 5000–180000. Start with one
round to establish native admission, then repeat the admitted cases. Output must
be fresh, outside input and dependency trees; the probe creates it with mode
0700. No browser is launched by the controls or build wrapper.

The terminal protocol is `R002F_NATIVE PASS|FAIL|INCOMPLETE|INCONCLUSIVE`.
Exit 0 means every requested candidate observation passed its bounded checks and
the descriptive baseline preview control completed if requested. Exit 1 means a
candidate check failed after admission. Exit 2 means incomplete setup or an
inconclusive discriminator. `result.json` contains the individual outcomes, exact
input identities, engine identity and private relative observation filenames.
Always quote the individual scopes alongside the aggregate status.

### Hosted campaign integration

The hosted coordinator can enable this probe through `campaign.json`:

```json
{
  "schemaVersion": 1,
  "engine": "chromium",
  "r003fDpr": 1,
  "r002f": {"enabled": true, "dpr": 1, "rounds": 1, "section": "all"}
}
```

Common preparation for the three published recipes runs first. Optional R002F
preparation uses a separate fresh `work/r002f-prepared` directory, retains its
process/build receipts and builder streams below private capture, and leaves
all disposable source outside capture. Its failure or absence records a blocked
R002F row without preventing the other prepared recipes from running. Both
immutable checkouts retain the exact R002B Pages receipt needed by the wrapper.

The planner rechecks both generated trees and binds the native command to probe
SHA-256 `673c0656d8e2d8e1c343d1258be5070fa9447f3f43878460791ea8570468558f`.
The coordinator requires the exact report protocol and requested population
before admitting `PASS`: three prayer scenarios per requested round when enabled,
and one baseline plus one candidate preview row when enabled, with matching
engine/DPR/round/section and observer/source identities. It preserves the
original `FAIL`, `INCOMPLETE` and `INCONCLUSIVE` statuses. The lane has a
900-second process bound and passes a 60000-ms page timeout. Missing or blocked
requested lanes remain explicit `NOT_RUN`/`INCOMPLETE` entries.

The 27 nonnative probe controls are registered as `r002f-hosted-native-controls`
with their complete input closure. The probe, builder and imported fixtures are
selected control inputs, so they are not duplicated as module/exclusion rows.
This classification adds no native qualification or verification-level promotion.

## Prayer restoration observation

Only `Date` is fixed. Timers, `performance.now()`, animation frames,
`IntersectionObserver`, `MutationObserver` and document visibility stay native.
The probe verifies that a real timeout and animation frame run while performance
advances and Date remains fixed. It never dispatches `visibilitychange` or
redefines `document.hidden`.

The fixture has six distinct prayer keys with times 05:00, 06:00, 12:00, 15:30,
18:00 and 19:30 in UTC. A real 2200-pixel spacer moves the actual card out of the
viewport. The source observer must set its real `.paused` class. While it is
offscreen the probe changes only Date, removes the spacer, and lets native
intersection delivery restore the card. Its mutation observer captures the
complete prayer DOM immediately after the actual paused-class removal, then
captures again in the next probe animation-frame callback.

| Case | Before UTC | Restore UTC | Essential boundary |
| --- | --- | --- | --- |
| Fajr | 2026-09-07 04:59:30 | 2026-09-07 05:01:30 | Isha/Fajr becomes Fajr/Sunrise |
| Maghrib | 2026-09-07 17:59:30 | 2026-09-07 18:01:30 | Asr/Maghrib becomes Maghrib/Isha; Hijri 25 becomes 26 |
| Midnight | 2026-09-07 23:59:30 | 2026-09-08 00:01:30 | Gregorian day changes; Hijri remains 26 |

Snapshots include current prayer, next prayer from `.until-prayer`, next time
from `.nt`, countdown, all six row labels/times/roles, progress, visible dates,
calendar disclosures/ARIA, arc HTML, six distinct marker keys and the expected
next marker, Sunrise's hollow ring, and the native SVG current-ring position.
The literal expected X positions use the source's 295-unit arc with a 1.3-unit
inset; their agreement with all six actual source-publisher instants is checked
by a nonnative control. Missing, duplicate or blank targets cannot pass.

For every pair, the baseline **must demonstrably be stale** in the restoring
task sample. An already-current baseline returns `INCONCLUSIVE`, including when
the candidate differs. Both arms must have the correct pre-hide setup and must
recover by the next probe rAF callback. A valid stale baseline plus a complete
current candidate is a pass for this DOM boundary only. The capture does not
measure a compositor-presented frame, a paint deadline or elapsed rendering
cost. The saved screenshots explicitly show the initial and later settled
states; they are not first-presented-frame evidence.

The fixture deliberately supplies only September 7 and 8. A request for a later
prayer day receives 503. This keeps the midnight next-day preview tail absent,
and the receipt records that constraint.

## Preview transaction observation

The real embedded preview and Moon owners remain active. The probe makes only
`/real-sky/native-sky.js` unavailable, deliberately preventing refined-sky
startup. Other local scripts and assets are served unchanged. The scene uses
00:10:05 UTC and disclosed lunar overrides: fraction 0.55, waxing, altitude 20,
horizontal position 42. The refined atmosphere still uses real ephemeris; these
images do not establish physical lunar-light coherence.

The candidate must first establish a current shared selector. Reads inspect the
actual computed CSS visibility of ordinary and staged native canvases, native
RGBA bytes, the selected receipt, solar mask and pure `MoonRuntime.observe()`
authority. Diagnostic reads never call the adopting `surface`, `state` or
`detailEnabled` accessors.

In one page evaluation, the probe wraps native `putImageData`, throws exactly
once for the staged sky canvas, calls the real preview updater, and reads the
selected layers before returning. The original canvas method is restored even
if the read fails. The selector, both selected canvas hashes, mask and frame UTC
must remain the admitted predecessor's. A successful real update must then
establish a new generation with an increased draw count at the same fixed UTC.
Holding UTC avoids introducing an unrelated Moon clock discontinuity during
the upload-fault test. It does not prove changed-scene pixel continuity. The
baseline's ordinary two-owner canvas comparison is descriptive; identical
pixels at unchanged UTC are not advertised as a mixed-pixel failure.

Finally, another single evaluation records a current selected predecessor,
advances Date by 2000 ms, calls the real Moon invalidation owner, and captures
the result immediately. The selected slot, ready class, frame receipt and lunar
authority must be withdrawn together. No intervening rAF is allowed. This is a
**clock-discontinuity authority revocation**, not a native visibility test.
Same-scope disposal is unsuitable: the unchanged owner may adopt an initial
successor before setting `disposed`; a source-pinned nonnative control records
that behavior and verifies the distinct actual invalidation callback.

Unestablished before/recovery/revocation setup is `INCOMPLETE`. Retention or
withdrawal failure after admitted setup is `FAIL`. An unexercised or multiply
exercised upload fault cannot count as a pass. Native canvas and CSS selection
are evidence of those browser states, not a guarantee about compositor output.

Both arms receive their admission verdict only after context cleanup settles and
the final request ledger is collected. An unexpected request, WebSocket or route
error makes the observation `INCOMPLETE`, including an event delivered during
cleanup. A context-close rejection is retained in `cleanupError` beside the raw
captured observations and also makes admission `INCOMPLETE`; it cannot discard
the row or preserve a successful earlier verdict.

## Local qualification and remaining work

```bash
node --test --test-reporter=tap tools/qa/hosted-native/r002f_probe_controls.cjs
```

The controls exercise the actual admission predicates with stale, empty,
duplicate, wrong-boundary and mixed-selection negatives; wrong-source build
admission; exact inventory identity; Date-only replacement; all six real source
prayer instants; and the unchanged combined Moon invalidation owner. The latter
uses the existing host fixture's controlled layout, transport, timers, initial
renderer and detail projector. None of those controls is native rendering
evidence.

Reconstruction and review-correction verification on 2026-11-25: 27 controls
passed. The additional controls run the actual preview observation/persistence
functions with explicit browser-boundary doubles, checking clean admission,
dirty baseline, ledger changes during cleanup for both arms and close rejection.
A real child emits both streams then exceeds its shortened test deadline; both
partial logs must survive, the child must be gone, and a successful child must
still return parseable builder JSON. These remain nonnative controls.

The disposable
canonical main build reported 0 written/117 unchanged on both runs; the combined
build reported 6 written/111 unchanged, then 0 written/117 unchanged. Both exact
entry/inventory identities matched, every one of the 116 listed generated files
verified, and both V1 tamper controls and Pages inclusion preflights passed.
The generated inventory itself accounts for the 117th builder output.

Native execution is still required to qualify actual observer ordering, native
canvas upload failure, real CSS selection, lunar withdrawal, and the requested
engine/DPR matrix. This reconstruction alone establishes none of those results.
Actual visibility/pagehide/bfcache, presented-frame latency, provider behavior,
extended motion and whole-scene aesthetic judgment remain outside this probe.
The original combined Moon result remains **244/248**, including the two RES
policy conflicts and two G8 fixture/policy conflicts; these are not waived.

## Purpose and authority

This route addresses the genuine local preparation failures on the selected R0035 receiving tree. Both original selected attempts and the isolated baseline diagnostic ended through SIGKILL; no timeout or cause has been established. Those receipts remain failures. ## Approaches and chosen design

Re-running the local builders is excluded by the observed failures and task instruction. Retaining only hosted summary receipts would leave the complete prepared file population unavailable for independent readback. Copying every prepared tree into the encrypted payload would exceed the convenient local opening footprint.

The chosen design is a separate workflow and source-only coordinator with a fixed immutable receiving contract. It invokes the unchanged original preparation/currentness functions and verifies their original native refusal. A raw content-addressed payload retains every logical file and its exact bytes once. An encrypted exact index binds a closed ordered set of at most 16 independently sealed object shards; each uses the unchanged portable transport and CMS envelope. The content-addressed encoding is an implementation choice for custody and storage; it does not change any product, original driver, scientific input or predicate.

## Private opening and independent readback

Root first authenticates the distinct workflow path, branch, exact workflow commit/tree, target commit/tree, run/attempt, jobs, artifact ID, length and digest. An authenticated transport envelope does not authenticate its sender. Root also verifies the saved private key's public component against the unchanged pinned recipient; the key remains local.

The earlier whole frozen task readback, now including its 458-byte runtime receipt, has 4,109 logical files / 1,470,547,303 bytes and 1,031 unique bodies / 501,768,979 bytes. This is an old 4c reader/size control, not preparation of the selected target. The actual new payload also includes complete admitted original source inputs, the 107-file receiving closure, the distinct harness closure, dependency inventories and fresh receipts. Its exact index totals govern opening.

Root keeps the downloaded artifact ZIP and extracted sealed set under `/home`. It opens and restores the small index first into fresh private directories, authenticates the complete binding and sealed-set population, and then opens one data shard at a time under `/tmp`. Every shard is restored into a fresh owned directory before exclusive raw-object acceptance into the workspace. The original opener can temporarily hold ciphertext snapshot, decrypted ZIP and extracted portable members; portable restoration and shard acceptance also need their own buffers. A conservative per-shard staging allowance is five times the actual shard ciphertext size plus 64 MiB. The completed unique raw-object population remains in the workspace. ZIP plus sealed-set bytes, all restored raw objects, index buffers, per-shard staging and safety margins must all fit their actual filesystems before private opening. No full 1.47 GB logical-tree expansion is needed. The 96 MiB OpenSSL input limit bounds input size; it does not claim a measured OpenSSL RSS ceiling.

Measured streaming compression of the old 1,030-body sizing subset would have reduced 501,768,521 raw bytes to 343,158,269 encoded bytes. The chosen raw-shard representation avoids introducing a codec while bounding each OpenSSL input. No compression layer, scientific predicate, counter, sample or wait was added.

The offline reader verifies complete object/population custody, actual source-only process/terminal semantics, exact retained target/current source closure, all 12 original command operands and deadlines, complete generated/source tree membership, transformation identity, source-readmission equality, installed-runtime before/after inventory equality and the specific native-refusal process. Immutable Git/source authority also requires the independently reviewed workflow/target identities and authenticated provider provenance; portable ciphertext alone cannot establish its sender. The reader never executes a retained source file or reconstructs a new live preparation task. It preserves hosted paths in the original receipts and reports relocated file lookup only as an explicit read-only map. It does not transplant the hosted preparation into a new native task. A subsequent native campaign still requires fresh native preparation, currentness, recipient gating and independent review. A failure during source input validation, dependency installation or an original builder remains `INCOMPLETE`; a later successful seal does not change the source process or workflow failure. A hard loss of the coordinator that prevents its final ownership/quiescence receipt causes sealing to refuse. Sealing failure never authorizes a plaintext upload.

## Exact reader and root opening interface

`r0035_source_payload.py` has no private-key operation. Root uses its separately reviewed provider authentication/download/key-custody wrapper with these interfaces:

1. Open the authenticated `index` envelope with the unchanged envelope code, and restore it with the unchanged portable transport. `load_index(restored_index, expected_binding)` requires exactly `index.json` and the complete externally authenticated binding.
2. `validate_sealed_set(index, sealed_root)` checks all and only the expected index/data envelope pairs, including directory population and exact indexed data ciphertext/envelope hashes and byte lengths.
3. For each index shard in ascending order, open and restore that one envelope into fresh private directories. `accept_shard(index, shard_id, restored_shard, object_root)` checks exact `shard.json`, bound source/run identity and every raw object before writing any accepted object. Existing accepted objects must be precisely all earlier shards and unchanged. An attempted duplicate, reordered shard, partial acceptance, extra object or substitution refuses. Partial failure paths must not be reused.
4. `inspect(index, object_root)` streams every unique body and checks complete logical references, sizes and hashes. `read_logical(index, object_root, path, maximum)` exposes a bounded read without expanding logical trees.
5. `r0035_source_preparation.py inspect --index RESTORED_INDEX --objects OBJECT_ROOT --binding AUTHENTICATED_BINDING.json` performs the source-specific retained readback. Exit 0 means `VERIFIED_HOSTED_SOURCE_PREPARATION_NATIVE_REFUSED`; exit 1 preserves a genuine `INCOMPLETE`. Neither status is native authority.

The binding has exactly `repository`, `workflowPath`, `workflowRef`, `workflowCommit`, `workflowTree`, `runId`, `runAttempt`, `targetCommit`, `targetTree`, `campaignSha256` and `contractSha256`. The workflow commit/tree and contract hash are supplied from the independently reviewed published harness, separately from the fixed receiving target. The encrypted index separately binds canonical full source-identity digests, literal original logical roots, ordered logical-file rows, unique full raw SHA-256/length rows and deterministic shard assignment. Each data descriptor includes the same binding and all five source-identity digests. The encrypted index binds each descriptor, portable mapping and sealed data pair. Provider authentication binds the outer index ciphertext and entire uploaded artifact; the index does not try to hash itself.

The root-only synthetic saved-recipient control can call `seal_collections` over small explicitly synthetic raw inputs, open each result with the saved key through the unchanged reader, and use the same interface to verify complete readback. Wrong binding, wrong recipient/public-key component, corrupted or truncated ciphertext, missing/extra/reordered shard and object substitutions must refuse. This control does not manufacture a hosted producer or selected-target preparation. No private key is accepted by the workflow, coordinator, payload module or its CLI.
